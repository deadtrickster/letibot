**Proposed changes**

## Synthesis

Checked by the orchestrator at 90dd9c84 where the reviewers disagreed on a fact.

- `#![allow(clippy::all)]` sits in 15 files: 9 crate roots (dialect-glm, flowy, harnessd, opencode, provider, sessionlog, tools, tui, turn) and 6 test files. Reviewers 2 and 3 counted different subsets; both are right.
- The reviewer VM arm still exists (`mergequeue/review.rs:700`, `Reviewers::Vm`). `fd6dafaf` changed the default to the host and deleted the test of the VM arm.

### Agreed by all three

- Little user-facing surface was lost. No CLI flag, slash command, MCP tool or session protocol frame was removed; the session protocol is still 54. The range is mostly additive.
- The headline new capabilities are real and tested against real sockets, daemons and stores: the room, the gate excerpt (a real ab5f7841 defect), one shared store connection per file, restart restore.
- The range's own guards were weakened. `3571db00` made clippy warnings errors, then `b9800494` added `#![allow(clippy::all)]` to 15 files, and a warm target dir lets the gate pass without linting. `22e29bc9` shows a test silently not running while the suite stayed green. `crates/bridge/tests/daemon_record.rs:84-89` passes without python3 by printing SKIPPED.
- Quality is poor: comments are 25% of added Rust lines; `harness.rs` is 26k lines with a 3,177-line `open_with_registry`; the queue pane has two renderers; `now_ms` has 14 copies and truncation helpers 38; harnessd tests share no support module; 106 notes were added and none rewritten.

### Disagreements and decisions

- Lost behaviour vs. correct retirement (sessions list: `d` fold, always-open `mine`, the groups contract). Decision: the retirement stands, but a plugin written against the old groups answer must be refused out loud, not no-op. Version the sessions answer.
- Reviewers on the host by default. Decision: keep the operator's ruling, but write it into DECISIONS.md and restore a test of the VM arm, so the isolated path cannot rot.
- Room protocol at v5 refusing any mismatch. Decision: bump only at release points from now on; N-1 compatibility is not worth the code while the room has no external users.

### Order of work

1. Guards first, because every later fix relies on them:
   a. remove the 15 `#![allow(clippy::all)]`, crate by crate, with targeted allows that carry a reason;
   b. make the gate's clippy step unable to pass on a warm target;
   c. a check that every `#[test]` sits on its own function (or count `--list` per binary);
   d. a skipped test fails on the gate host instead of printing SKIPPED.
2. Contract fixes: version the sessions plugin answer; restore the reviewer VM-arm test and record the host default; the single-attempt retry test.
3. De-duplication: one queue renderer; one `now_ms` and one truncation helper; `crates/harnessd/tests/common`.
4. Deslop per `hands-off/templates/deslop.md`: comments to the 2-3 line rule, notes merged into rewritten topic docs.
5. Structure: split `open_with_registry`, `rounds` and `run_to_completion`; break `harness.rs` into modules.
