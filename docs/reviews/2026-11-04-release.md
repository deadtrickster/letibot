## harnessd

### Round 1, reviewer 1 (against the claims), deepseek

**Thesis.** The three subsystems that decide what the model is *told* about its own state (restart, compaction, child results) each degrade silently in a documented-looking way. Nothing crashes and nothing is lost from disk, so the failure mode is an operator and a model that both believe something was restored, summarised intact, or delivered, when it was not. That is the worst shape for daily use.

**1. "A session survives a restart with its pending work."** It survives for one hour, on an orderly stop, when a store is configured, and only as prose. `RESTORE_WITHIN` is 3600 s (`crates/harnessd/src/restart.rs:74`) and `Stopped::restores` requires a known stop time (`restart.rs:178-181`), so a session reopened after lunch, or a daemon whose life row is missing (`Stopped::Unknown`, `restart.rs:230`), restores nothing. `restore_after_restart` returns early with `None` when `self.cfg.store` is `None` (`crates/harnessd/src/harness/turns.rs:645`), producing no notice at all. Jobs are never re-run; the model is "reminded (not re-run)" (`restart.rs:660-665`). And the pending tool calls of an interrupted turn are not answered by the daemon but by a filler string the provider writes into the prompt: `"[no result was recorded for this call: the turn ended before it …"` (`crates/provider/src/messages.rs:700-705`). The model resumes from words no tool produced, and the operator sees a card that says "restored".

**2. "Compaction keeps the prefix stable and loses nothing the model still needs."** The module header refutes the second half for the backend most operators will use: on a cloud provider "none of the prefix machinery applies to it at all" (`crates/turn/src/compaction.rs:22-29`), and the cloud path is `plan_fold` plus `summarise_first_half`, which replaces the first half of the conversation with a record capped at 15% of the free room (`SUMMARY_FIDELITY_PER_MILLE = 150`, `compaction.rs:96`). At least 85% of the folded span's content is gone by construction, every fold reprices the whole prompt (no cached prefix), and `plan_cut` returns `Hopeless` when the prompt crowds the window (`compaction.rs:1174-1178`), which is the case the wall exists for.

**3. "A child's result always reaches its parent."** It reaches one reader once. `TaskSlot::hand_over_answer` drops the body after the first delivery (`crates/harnessd/src/harness/children.rs:151-181`), and a second `task_result` on the same handle returns `ANSWER_HANDED_OVER`: "this answer was handed over and the tree does not keep a copy of it" (`children.rs:159-160`). A model that re-checks a child, which nags encourage, gets a sentence where the tool promises an answer.

**What I concede, with evidence.** The merge queue holds up better than I expected: the landing is a compare-and-swap against the gated tip (`crates/harnessd/src/mergequeue/serve.rs:2739-2755`), a red target halts both queues (`serve.rs:1934-1974`), and a branch that moved after approval goes back to review by change-id (`serve.rs:2126-2146`). Plugins look genuinely one-way: the call hook runs before the gate and the gate adjudicates the rewrite (`crates/harnessd/src/plugins.rs:2101-2103`). Two housekeeping notes: the far side ran out of disk, so every `bash` call failed and this is code reading only, no build, no test, no git; and the review docs I cross-checked are already stale (`job_wait`'s description now says the completion arrives on its own, `crates/tools/src/builtins/jobs.rs:676-682`, though `TODO.md:105` still lists it open).

**Changes.** (a) Say the threshold and the outcome in the notice itself, and raise a warning when a session with no store cannot be restored. (b) Make a fold's transcript row state that it is lossy and at what ratio, and keep the folded text readable. (c) Hold a child's answer until a second read or a TTL, rather than dropping it at the first.

**Anticipating.** "Ready for daily use" answers crashes; my point is quieter and survives that defence: the prose outruns the code exactly where the operator is least able to check. "Fragile regardless" misses the same distinction; I am not arguing the code is brittle, I am arguing it does not do what it says.

### Round 1, reviewer 2 (for release), deepseek

**Reviewer 2 of 3, FOR release, subsystem harnessd + plugins, at 21dae760.**

**Thesis.** All five claimed behaviours have a real path from door to witness, and the one that could cost the operator irreversibly, landing a commit, is guarded by a compare-and-swap on a tree that was gated after being rebased onto the live tip. The other four fail safe, in the direction of *saying* rather than silently doing. Blockers: none. Must-fix: three lines of code and one sentence of policy.

**Evidence.**
1. *Restart.* Records are stamped with the instance that wrote them, so an attach is not a restart (`crates/harnessd/src/restart.rs:6-10`); the down time comes from a `Lifeline` row (`restart.rs:84-111`). End to end: `crates/harnessd/tests/restart_restore.rs:366` drives a real store, stops a real daemon mid-child, reopens, and asserts the child resumed (`:528-537`, `resumes == 1`) and that its answer reached the parent (`:528`). Over the threshold it reminds rather than resumes (`restart.rs:178-185`).
2. *Child to parent.* `child_completion_wakes.rs:533` wakes a parent with nobody calling `task_result`; `:703` delivers a settlement for a session that was closed when the child ended, at its next open. A busy parent is not interrupted: results are held and released at the round boundary with a cap (`delivery.rs:15`, `harness/turns.rs:395-430`), and the held batch is drawn last so it cannot displace the plan line (`harness/tests/delivery.rs:526`).
3. *Queue.* The verdict is bound to the head it judged and a moved branch goes back to review (`serve.rs:2124-2147`); the landing rebases onto the live tip (`:2196`), reads the gate from the **target's** tip so a branch cannot weaken its own gate (`:2211`, `gate.rs:1988`), runs it on the rebased sha (`:2267-2280`), then swaps with `git update-ref <ref> new old` (`:2741`, `git.rs:763`). A target that moved during the gate is re-queued, never forced (`:2739-2755`).
4. *Plugins.* The hook may not change the tool's name, a rewrite is re-gated because the patch is applied before the gate block (`runtime.rs:1556-1640`, `:1801`), `access_for` can only narrow (`:1794-1800`), an `answer` never runs the tool and carries a by-line naming the layer (`plugins.rs:2179`), and the gate itself is a process spawn with no plugin in its path (`gate.rs:1135`).
5. *Compaction.* `prefix_fingerprint.rs:108-207`: an unchanged prompt is silent, a changed one names `/reseat`, and the resume replays the fork (`transcript_id == "s#t1"`) instead of re-prefixing; the tail is kept verbatim inside the `WRITE_ROOM` reserve (`turn/compaction.rs:1173-1204`).

**Proposed changes (minimal).**
- `restart.rs:31`: the bullet list has collapsed into one unreadable line, and this module's header is what the operator will read when it goes wrong.
- `harness/tests/delivery.rs` sibling in `runtime.rs` (the rewrite test): the assert message says "the gate judged the model's arguments, not the layer's" while asserting the layer's. The next reader will believe the message.
- `serve.rs:2778-2814`: a lost push still marks the row landed on the local target. Keep the decision, make the state say "landed locally, not pushed" instead of only a warning.

**Concessions.** The one-hour restore is policy, not durability: a session down longer is reminded, not resumed, and a job is never re-run. A parent that never reopens hears its child only through `task_result`. I read the suite; read-only forbids running it, so my claim is "these tests exist, are not `#[ignore]`d, and assert the right thing", not "they are green today".

### Round 1, reviewer 3 (against both, fragile regardless), opus

Thesis. The main paths are written with care and are documented thoroughly. The code that hands work between owners is fragile, though. Settlements route through a hierarchy of `stop` flags read without the locks of the queues they guard. The store's "delivered" bit is set before the text is durable. The merge queue fails open on a store error and lands train prefixes that were never gated. Plugin policy fails open. On the failure paths a user sees silence, not an error.

Evidence.

1. A child's result can be lost when an ancestor closes. `SettlementQueue::push` reads its own `stopped` under its own lock (`jobwatch.rs:1136`). It then calls `above.route()` (`:1141`, `:272-280`), which reads the ancestor's flag `Relaxed` with no lock held. It drops `g` and pushes. If the ancestor's `stop()` (`:963-975`) drains between the route and the push, the completion goes into a queue nobody reads. `stop()` (`:985`) and `settle_up` (`:598`) have the same gap. At the root, `stop()` discards held and queued settlements in memory (`:977-981`). Only a later `deliver_settlements_left_undelivered` (`harness/turns.rs:550`) brings them back, and only if the same instance reopens the session.
2. Delivered is marked before it is durable. `at_round_boundary` calls `immediates`/`batch`, which call `read_now` (`harness/deliveries.rs:660`, `:681`). That writes `delivered` to the store (`jobwatch.rs:722-731`) before the steering text reaches a persisted transcript row (`hub_io.rs:284`). A crash in that window means restore believes the result was told. The door path has `put_back` for this (`harness.rs:1155-1166`). The steering path relies on the in-memory `handed_back` only.
3. Restart restores work only if the session is reopened within `restore_within` (default 1h) of the stop (`restart.rs:178-181`). After that, children are only listed in a reminder. Jobs are never re-run.
4. The room wake queue is process-global and unbounded (`room/wake.rs:8-17`). Nothing removes the entry of a session that closes, so it leaks for the life of the daemon.
5. Merge queue, a lease error lands anyway. `if !self.beat().unwrap_or(true)` (`mergequeue/serve.rs:2726`, `:2924`) treats a store error as "lease held". There is also a gap between the lease check and `update_ref_cas` (`:2741`).
6. Merge queue, ungated tips. The train is gated once on its final tip (`serve.rs:2443`). If a CAS fails partway (`:2933-2958`), cars `0..k` stay landed, and the target now sits on an intermediate tip that was never gated, with nothing pushed.
7. Merge queue, half-moved checkouts. `follow_checkouts` (`git.rs:799-808`) moves checkouts one by one with `read-tree -m -u` and stops at the first failure. The CAS undo (`serve.rs:2757`) puts the ref back but leaves the checkouts that already moved on the new tree. They read as dirty against a ref that did not move. If the undo fails, the row still reads Blocked while the target holds the commit.
8. Plugins, fail-open. A layer that traps, runs out of fuel or returns malformed output gets `Step::Passed` (`plugins/src/stack.rs:1015-1024`). Once `MAX_CALLS` is reached, every remaining layer passes (`:1003-1012`), including a lower layer that would refuse. A malformed verdict runs "as the model proposed" (`harnessd/src/plugins.rs:2131`). The SDK says a layer "can only make a call smaller" (`plugin-sdk/src/tool_call.rs:2`), but nothing checks that. `Rewrite` accepts any arguments (`tools/src/runtime.rs:1600-1625`).
9. Compaction. By design it re-seats with the tools this daemon has now (`harness/wall.rs:1071`), so the prefix changes and tools can disappear (`adopt_reseat` reports them as `lost`). A summary that proposes tool calls is refused. Its instruction and answer stay in the transcript (`:1258`), so each retry at the wall uses up context that is already short.

Proposed changes.
- Route upward under the target queue's lock. Re-check `stopped` after taking the lock and retry if it changed. Use `Acquire`/`Release` ordering.
- Call `read_now` from the transcript write, not from the take.
- Change `beat().unwrap_or(false)`. Run the lease check and the CAS under one store transaction, or fence them.
- Have a train land all its cars or none. Use one CAS to the final tip, or gate each prefix.
- Run `follow_checkouts` as a dry run on every checkout before any of them moves.
- Make a guard layer's failure close the call for `on_tool_call`, and say so. Enforce "smaller" or delete the claim.
- Bound `room/wake.rs` and clear a session's entry when it closes.
- Roll back the refused summary turn.

Concessions. A plugin cannot change the tool name. A `Rewrite` is gated again (`runtime.rs:1762-1800`), so a plugin cannot widen the gate past the session's mode. Only a refusing layer can be undermined. Restore within the same instance (`turns.rs:550-620`) and the `put_back` on the door path show these races were thought about. The CAS on the single-branch path does stop a branch from landing on a target that moved. Against the "ready" reviewer: these are edges, not the main path. But an operator who uses the queue and children every day will hit them. Against the "does not do what it claims" reviewer: most of the claims do hold on the path the tests cover. The failure modes are what goes unverified.

## tools

### Round 1, reviewer 1 (against the claims), deepseek

**Thesis.** At 21dae760 the tools layer advertises one boundary with two renderings. It ships a macOS-only fence, a Linux default seat with no boundary at all, a never-write rule that refuses reads by spelling, and a token path that ends in a file the model is handed the name of. An operator reading docs/§4k on lubuntu1 (this box) is misled about what confines a command.

**Evidence.**

1. The wide seat is macOS-only, and the level code says otherwise. `Level::of` / `seat_for_level` (seat.rs:118-137) are platform-neutral and unit-tested, but the sole caller is `#[cfg(target_os = "macos")] default_seat` (open.rs:695), and `seatbelt_for_unconfined_seat` is an empty stub elsewhere (open.rs:758-760). On Linux a default (`leticode`) session falls to `HostBackend::executable("/")` (open.rs:824-826): no namespace, no view, `~/.ssh` readable and writable. `ViewSpec` has no deny field (confine.rs:510-527) and the bwrap home arm is a plain `--bind` (confine.rs:2205-2208), so `DENY_UNDER_HOME` has no Linux rendering. Docs 794-799 promise the fence with no platform caveat.
