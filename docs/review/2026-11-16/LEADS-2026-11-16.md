# Review leads found live on 2026-11-15 and 2026-11-16, outside the panels

Snapshot: 9e9312b06. These were found while operating rano, db-fuzz and the landings. They are leads for the panels and for the integration. Each is a verified observation unless marked HYP. The fixed ones are kept so the panels can check that the fix holds.

## Fixed, or on a branch, with the cause recorded

1. **A slash command was handed back to its own thread forever** (R308, landed).
   - What happened: a `/nag pause` from the head looped at about 35k hand-offs/s. Delivery stalled ("waiting on: delivery"), and the command finally ran only when the daemon stopped.
   - Cause: the `CommandKind::Slash` arm in `crates/harnessd/src/sessions.rs` handed the command back without the `open` check.
2. **A single `c` in the todos pane paused the nags,** and the pause survived restarts as "until resumed" (R311, landed). The operator never asked for a pause. The `/config` nags row could not toggle it.
3. **A job result counted as delivered when it was batched into a turn**, so an interrupted turn could lose it. Split-store reads of project tables went to shared.db and failed silently, so restore never re-delivered anything (R313, landed; 84 store methods are now covered on split stores).
4. **The usage figure was stale** (`5h 47%` while the truth was 60%) (R310, landed): failed polls kept the old figure, the poller kept the key it started with, and a crashed poller never restarted.
5. **A reviewer asked the operator to read its own spill file** (R315, landed). The view never held `<owner>/tmp/spill`. With `[gc] root` set, CARGO_TARGET_DIR and TMPDIR never reached commands at all.
6. **Grants lived only in memory.** Each reviewer is a new session, so a grant answered once was asked again (R314, landed).
7. **digest was broken on every default seat** (R318, branch `digest-role`). It hardcoded the `researcher` role, and 6ea755cf0 put a role check in front of every child start. The merge queue's red-tip fixer (`coder`) was refused the same way.
8. **A job-wait note fired 10 minutes after the model had already acted on the job, as a turn-less row** (R319, building). Wanted: resolve the wait at delivery; the sweep is a backstop only.
9. **The restart looked hung for about 40s with no output** (R312, landed). The time on resumed rows was the resume's clock, not the time the row was stored.
10. **The compaction looked hung** (R298, landed): about 4m44s with nothing on screen, then the full summary dumped inline. The header ctx stayed stale after the compaction.

## Decisions taken by the operator during these days (for the decision section)

- Stability over features. Fix-only phase until critical and high are closed.
- No hardcoded paths for reviewer reads (no /build or /data defaults). Grants are stored, and a relayed queue answer covers the queue until revoked.
- The shadow becomes layer B (`AuthorisationOracle`) of automode. Stages per R316 are promoted by the operator on replay evidence, never automatically.
- Nags on by default. A pause never survives a restart.
- `on_limit = "wait"` for rano (project file `~/Projects/rano/leticode.toml`).
- Reviewers may run one named test, never a whole suite.
- Review results live in markdown in the repo, never only in a transcript.

## Found while running the review itself (2026-11-16, morning)

27. **(HYP) An unknown mode name silently runs writes-allowed.** A canary showed `Mode::parse` refuses an unknown name (`crates/tools/src/mode.rs:440-458`), so the suspect is the bridge's `leticode_start`, which may drop the error and use its default. `leticode_start` with mode "read-edits", which does not exist in this build, started sessions in the default writes-allowed mode instead of refusing. A mistyped mode widens a session. It must refuse and list the valid names. Area: A2/P8. Severity: high.
28. **A second leticode_start in the same folder silently replaces the first session.** Parallel starts in one workspace replaced each other within minutes, and the replaced sessions vanished ("no such session") with no report. A start in an occupied folder should refuse, or name what it replaced. Area: A4/A8.
29. **Stopped orchestration leaves daemons running.** Stopping the review workflow left 9 harnessd daemons running review sessions on DeepSeek, GLM and Kimi. Nothing ties a leticode session's life to the caller that started it. Area: A7/P5.

30. **The Claude Code bridge (letibot-mcp plugin) speaks protocol 74 while daemons speak 78.** The plugin's MCP server binary is older than the installed build, and nothing restarts it after an install. Area: P1/P7 (same family as lead 24).
31. **Only `bash` moves itself to the background after the threshold** (`auto_background`, `crates/tools/src/builtins/bash.rs:266-276,462-469`). Other long tools hold the turn for as long as they run: `digest` (13 sequential part reads), and likely `task` waits, `web_fetch` and `search`. The operator expected `digest` to be backgrounded after 1 minute. Proposal: one rule for every tool - past the threshold a call becomes a job with the same settlement path. Area: A1/A10, coherence.
32. **`digest` is a hard-coded workflow.** It splits the input, fans out helper children, and folds their answers sequentially. Yet it runs inline, holding the turn, while every helper is already a background child. Proposal for the plan: a single orchestration primitive in letibot that runs as a background job and settles like a `task`:
    - fan-out, fold, verify, with a resume cache;
    - `digest` becomes its first script, and other fan-outs follow (review panels, sweeps, rebases);
    - it carries the workflow-stability rules: own worktree per child, waits on child exit only, a canary first, no silent caps, and a backup before resume.
    Area: A10 plus the workflow-stability plan item.
33. **`leticode --model X` in a one-shot is silently ignored.** It prints "--model is a config setting now: `[default] model` in providers.toml" to stderr and runs the default model. All 60 "external" review positions ran on deepseek-flash this way, while the bridge's `leticode_start` honours `model`. `--provider NAME` works. A flag the launcher accepts and then ignores must refuse instead. Area: P7 (launcher). Severity: high, because it silently changes which model and provider answer, and so what is billed.
34. **`ps` printed raw command lines, so an argument with newlines split one row over many lines.** Fixed in e1cca6a40. It was found because `builtins::ps` tests read the box's live process table and failed deterministically while review one-shots were running. Another test reading live box state (P6).

37. **The review fan-out spent the operator's Kimi 5h window** (20 positions at about 2M prompt tokens each), which parked rano for about 3h. Fan-outs must budget each provider's share against its live window before launching. Area: B16, workflow stability.

The last still says "the turn it stopped goes on by itself", long after that turn finished. Area: A9 / B15, together with #41.
