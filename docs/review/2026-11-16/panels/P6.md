### Position 1 (GLM)

[model: glm-coding (the preset's default model)]
THESIS. Position 1. The tree has two gates and dozens of test harnesses, and only the shell gate isolates the operator's home — partially, and with her key material deliberately linked back in. The queue gate runs unreviewed test code with the daemon's real HOME; several lib tests read the operator's live config by construction; the "loud skip" is inaudible to gate-at.sh's own pass rule.

FINDINGS

1. **The merge-queue gate inherits the daemon's whole environment.** `harnessd/src/mergequeue/gate.rs:474-480` (`StepEnv::apply`) sets only target, TMPDIR, jobs; `run_step` spawns `sh -c` with no env clear (`gate.rs:1219-1238`). The gate block the queue runs (`AGENTS.md:73-82`) is `cargo test --workspace --no-fail-fast -- --nocapture`. **High.** Scenario: a branch under gate carries a test reading `~/.config/letibot/providers.toml` or `keys/`; `--nocapture` prints it into the gate log, which is kept on the queue row. Fix: `apply` must move HOME/XDG into the step scratch (as gate-at.sh does) and the two gates must share one env builder.

2. **gate-at.sh links the fleet private keys into the test HOME.** `scripts/gate-at.sh:40-42` symlinks `~/.config/letibot/keys`, `hosts.toml`, `known_hosts` into `$G/home` — the exact material I17 says never enters a test context — while its own header claims "a test that forgets to isolate its data dir must not reach the operator's store" (`:30-31`). **High.** Same exfiltration channel as (1), lead-side, on a stack of not-yet-landed branches; `.gitconfig` is copied too (`:35`). Fix: generated throwaway keys under `LETIBOT_HOSTS`; nothing of the operator's linked.

3. **A skip is a green "ok" that gate-at.sh cannot see.** `tokencore/src/apparatus.rs:68-84` skips via `eprintln!` + return; gate-at.sh sets no `LETIBOT_REQUIRE_APPARATUS` (`scripts/gate-at.sh:54-55`) and judges by `ok -lt 140` plus FAILED/error greps (`:58-63`), so a silently-skipped suite counts as ok. **Medium.** On any box without the GGUF, `restart_notice` (`harnessd/src/harness/tests/restart_notice.rs:72` → `vocab_gguf`) and friends vanish and the stack gate says GREEN. Fix: export the var and grep the log for `THIS IS NOT A PASS`.

4. **`the_box_publishes_which_providers_it_holds_a_key_for` reads the operator's providers.toml and live key envs.** `harnessd/src/config/tests.rs:407` calls `keys::resolve(p, None, None)`; `for_this_box` leaves `providers_file: None` (`harnessd/src/config.rs:1763`), so `resolve` falls to `config_file()` — `XDG_CONFIG_HOME` first, then `HOME` (`crates/provider/src/keys.rs:194-201`) — then real key env vars (`keys.rs:236-239`). **Medium.** Box-dependent assertions on live credentials (I18). Fix: the crate's own scratch helper (`config/tests.rs:2380`) plus a scrubbed env; same for `letibot/tests/sudo_ask.rs:79-104`, which moves only `XDG_RUNTIME_DIR` (`:75`).

5. **Agent-run tests inherit the live socket.** `harnessd/src/harness/open.rs:1367-1376` injects `LETIBOT_SOCKET`/`LETIBOT_SESSION`/`HOME` into every spawned command; `bridge/src/daemon.rs:219` treats `$LETIBOT_SOCKET` as authoritative. Per-crate `remove_var` guards (e.g. `bridge/tests/transcript.rs:3`, "process-wide") race under libtest parallelism. **Medium.** An agent following the standing rule `cargo test -p <crate>` runs binaries that can attach to the operator's live daemon. Fix: spawn with the vars removed unless a test opts in.

6. **`gguf_path` falls back to the literal `/home/dead/models/...`** (`apparatus.rs:31-48`), so even gate-at's moved HOME finds the real model on this box. Low; also makes (3) invisible here. The models-dir config test (`config/tests.rs:42-60`) passes a scratch data dir (`:55`) — its box-dependent failure path untraced (HYP).

CONCESSIONS. gate-at.sh does move HOME/XDG/data/state and unsets `XDG_CONFIG_HOME` (`:32-55`); daemon tests got private runtime dirs (f3fddd6b4, verified `sudo_ask.rs:68-77`); `sudo_ask_live` is `#[ignore]`d; the queue's gate does set `LETIBOT_REQUIRE_APPARATUS=1` (`AGENTS.md:77`) — which is exactly why (1) matters: the strict gate is the one with the real HOME. To position 2: fixes are real but per-crate and hand-rolled. To position 3: agreed — seven env resolvers and no shared test-env helper is the root cause my findings instantiate.

### Position 3 (Kimi)

[model: kimi-code-global (the preset's default model)]
Thesis: Test isolation is not a boundary; it is per-file convention. The manual gate, queue gate, unit tests, and config readers each implement different environment policies. Patching individual tests (position 1) is whack-a-mole, while green runs with scratch directories (position 2) do not prove isolation.

Findings:

1. High — Gates execute branch code with ambient credentials and daemon authority. The queue’s `StepEnv::apply` sets only target, TMPDIR, and jobs (`harnessd/src/mergequeue/gate.rs:474-479`); `run_step` then spawns `sh` without `env_clear` (`gate.rs:1219-1238`). The manual gate likewise preserves the environment except two XDG variables (`scripts/gate-at.sh:54-55`) and symlinks real fleet keys into its supposedly isolated HOME (`scripts/gate-at.sh:38-42`). Agent commands receive the live socket and session (`harnessd/src/harness/open.rs:1367-1373`), and provider resolution accepts inherited key variables (`provider/src/keys.rs:236-247`). A branch test can therefore read credentials or contact the live daemon despite scratch HOME. Change: one shared gate launcher using `env_clear`, an explicit allowlist, fresh HOME/XDG/runtime directories, no credential/socket inheritance, and no real-key symlinks; live-resource tests require a separate explicit opt-in.

2. Medium — Process-global environment locking is incomplete even within harnessd’s lib tests. `HOME_ENV` is the supposed common lock (`harnessd/src/lib.rs:29-32`), and the plugin test mutates HOME/XDG under it (`harnessd/src/plugins/tests.rs:545-567`). Concurrently, `the_box_publishes_which_providers_it_holds_a_key_for` resolves every provider without that lock or a fixture file (`harnessd/src/config/tests.rs:380-407`); `Config::for_this_box` leaves `providers_file: None` (`harnessd/src/config.rs:1763`). Interleaving can make its two key-resolution passes disagree, or resolve the operator’s real file/environment. Change: eliminate test-time mutation through injected immutable `Env`/config-path values; put genuinely process-environment-dependent tests behind one per-process fixture.

3. Medium — Config path semantics actively disagree. Plugin paths treat empty XDG as unset (`plugins/src/paths.rs:36-56`), while provider keys (`provider/src/keys.rs:194-200`), permissions (`tools/src/permission.rs:672-678`), and legacy modes (`harnessd/src/modes.rs:40-44`) accept it as a path. With `XDG_CONFIG_HOME=`, plugins/trust come from HOME while providers and permissions resolve under `cwd/letibot`; tests and production consequently read different authority depending on cwd. Change: one shared resolved-paths type for every crate, with conformance cases for unset, empty, relative, and overridden paths.

4. Medium — Scratch HOME does not isolate model apparatus, and the manual gate accepts skips. GGUF discovery falls back to literal `/home/dead/models` (`tokencore/src/apparatus.rs:18-25,31-48`); restart tests load that vocabulary (`harnessd/src/harness/tests/restart_notice.rs:72,102-108`). Thus an “isolated” gate still reads host models, while hosts without them can skip and pass because `gate-at.sh:54-55` omits `LETIBOT_REQUIRE_APPARATUS=1`. Change: explicit test-supplied model fixtures, no production absolute fallback, and mandatory apparatus/skip accounting in every gate.

Concessions: Private runtime directories, one-test binaries, `plugins::paths::Env`, and opt-in real-store checks are useful local fixes. They are not shared enforcement and do not cover the queue gate or existing ambient readers.
