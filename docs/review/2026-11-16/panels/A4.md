## Round 1

### P1 - GLM

[model: glm-coding (the preset's default model)]
THESIS: A4's authority model is a caller-side argument, not a property of the connection or the row. Every door that mints a turn defaults to `Speaker::Operator`, and every restart path re-derives identity from a snapshot. So across the child and restart seams, agent text becomes operator text and ceilings go stale — exactly where the system claims R306/R313 closed it.

FINDINGS

1. HIGH — The subagent brief is stored and trailed as the operator's words.
`crates/harnessd/src/harness/children.rs:4223` runs `h.submit(&brief)`; `submit` is hardwired `Speaker::Operator` (`crates/harnessd/src/harness/turns.rs:201-202`), which writes the trail (`turns.rs:337`) and the row (`turns.rs:291-297`) as Operator. The brief is the parent model's `task` prompt text. The correct door exists and is unused here: `submit_a_parents_message` (`turns.rs:1610`) speaks `Speaker::Agent`.
Failure: the child's gate oracle cites operator utterances; `cited_operator_words` (`crates/tools/src/authorise.rs:166`) only checks a cite names an Operator row — a brief saying "run whatever is needed, don't ask" is citable operator consent *inside the child*, i.e. the agent authorising itself, the exact thing the check exists to stop. The reseed (`crates/harnessd/src/harness/trail.rs:107,137-141`) carries it across restart, and `fork_session` copies the row into parentless sessions.
Fix: send the brief through a speaker-carrying door (Agent + parent id), as `parents_message_turn` already does.

2. MEDIUM — A reopened child's ceiling is a snapshot; its own mode row is never read.
`crates/harnessd/src/harness/open.rs:2212-2217`: `parent_ceiling` is a fresh cell of `cfg.mode`; only a spawn hands over the parent's live cell (`children.rs:4114`, `harness.rs:846`). And `open.rs:669-676` gates the session's own mode row on `parent_session_id.is_none()` — the row `narrow_to_parent` writes (`harness.rs:875`) is never read back for a child.
Failure: parent narrows to `review`; daemon restarts; the child reopens (resume, park-return, any path not the parent's runner) with a ceiling equal to whatever point the reopen cfg carried. The parent's narrowing never reaches it; `/mode` widens freely inside the stale ceiling; `within_parent` (`harness.rs:813`) checks against the snapshot, not the parent.
Fix: at open with a resolved `parent_session_id`, clamp to the parent's stored point and read the child's own row as a floor.

3. MEDIUM — `/fork` and the limit-hook fork drop point and parentage.
`crates/harnessd/src/harness/fork.rs:91-113` mints a parentless session; `limit_hook.rs:334-361` continues a live turn there. The fork reopens as a root (empty own row → project store/daemon default, `open.rs:669-724`), so a narrow child's continuation runs with no ceiling relationship — and a `limit_decide` layer can trigger it.

4. MEDIUM — The restart journal drops `from`.
`crates/sessionlog/src/hub.rs:773-781` restores `from: None`; `QueuedCommand::peer` (`hub.rs:87-94`) then recognises only identity `letibot-mcp`. A queued prompt sent `from: "cc@x"` under any other head identity is replayed as the operator's. Mechanism verified; reach beyond the bridge HYP.

5. LOW — Undelivered settlements have no sweep: rows stay `delivered = 0` until that one session's next open (`turns.rs:810-812`); a never-reopened session's settlements are said to nobody.

CONCESSIONS
R306's live-cell handoff is real and tested (`harness/tests/child_mode.rs`); the gap is the reopen path, not the spawn. R313 is coherent: the gone-daemon case is handled (`turns.rs:959-971`, marked at `:903`). R311 holds (`nags.rs:626-661` drops an earlier daemon's pause). To position 2: your tests cover spawn-time clamping and the parent's own restore — none covers a child reopened outside its parent's runner. To position 3: the defect is not the 45k lines; it is that `submit` defaults to Operator at all. Identity should be derived from the sender, never defaulted.


### P2 - Claude fable

THESIS

WHAT HOLDS (verified in code)

Automatic restore and `task_resume` both go `resume_run` (harness/children.rs:2267) -> `spawn_child` (:2308) -> the same seat path: `mode: point` read live (:3946), then `sub.follow_parent(self.point.clone())` (:4114). A grandchild comes back the same way (:4208). Spawn clamp: harness/open.rs:2874-2875. One width check, `within_parent` (harness.rs:813), before any state moves (:765).

2. P8's HYP is resolved: the parent link survives a restart. Registry resume takes `on_disk.parent_session_id` (sessionlog/src/registry.rs:2324-2325), and open applies `parent_for` (harness/open.rs:740). A reopened child is never seated as a root. Its worst point is the daemon's base (`UNSEEN_PROJECT = ALWAYS_ASK`, tools/src/mode.rs:651, or the operator's flag).

3. Restore window: `Stopped::restores` measures stop -> session open (restart.rs:257-260), a crash is dated from the last beat (:305-308), an unknown stop restores nothing (:259 via `at_ms`). A live daemon's rows are not taken (`is_running`, :320-336, pid checked).

4. R313 marking is uniform: all eight doors mark inside `opened` (harness/turns.rs:352, 690, 792, 1562; nags.rs:439; wall.rs:353, 388; limit.rs:371), and an unopened turn puts everything back (turns.rs:722-740). `wake` refuses once stopping (:440, :668).

5. R311: `restore_nag_pause` (harness/nags.rs:626-662) drops an older daemon's pause with one row.

FINDINGS

F1. MEDIUM, new. A job running at the stop is marked delivered before its notice is stored. harness/turns.rs:1308-1315 writes `lost at restart` and calls `deliver_job` immediately; the line lives only in `self.restart_notices` (memory, ~:1293). Same at :1043-1047 for relics. R313 fixed exactly this for settled jobs via `restart_owed` (:1259) and skipped this branch. Scenario: `letibot --restart` twice in a row (bad build, restart again). Second daemon skips the row (state is neither `running` nor stopped-with-daemon, :991; delivered, so not in `undelivered_jobs`, :1026). The model is never told the job died, and a todo row waiting on it waits forever. Change: push the handle to `restart_owed`, mark in `restart_owed_stored` (:903); keep the state flip.

F2. HIGH, concede P4 A2, area evidence. `opened` runs unconditionally after `persist()` (turns.rs:1713-1714), and `persist_rows` returns Ok on `BusyWait::Leave` (:4507). So "marked when stored" is false on a stop during a busy store. Bound: needs a person's interrupt plus a locked store plus a daemon death before the next write. Change: call `opened` only when every row was written.

F3. MEDIUM, narrows P8 A2. The only unfollowed child is one reopened through the worker door (sessions.rs:2155-2164) while no parent thread owns it (:2143 refuses otherwise), e.g. parent reminded-not-resumed past 1 h. It opens at the daemon base, and the row `narrow_to_parent` wrote (harness.rs:866) is never read (open.rs:669-673). Scenario: daemon flag `allow-all`, parent narrowed to read-only, orphan child reopened by a head: wide. Change: for a child, read its own row and take the narrower of row and base. Test.

F4. LOW. `daemon_life_started_ms` is lazy (nag_pause.rs:102-105) and compared on wall time. A second daemon sharing the store drops a live daemon's pause on open. Fails toward nags on.

CONCESSIONS
- Brief as `Speaker::Operator` (children.rs:4223): real (P2 A1). The mode clamp bounds what the child can do, not what its oracle believes.
- Narrowing lands at batch boundaries (turns.rs:1826, 2652); a running call keeps the wider point.
- A failed `narrow_to_parent` only warns (harness.rs:890-897).

ANTICIPATING
- Position 1 will cite "reopened child after restart" as an identity break. It is F3 only: the restore path hands over the live cell. Their best points are F2 and the brief.
- Position 3 will call open/reseat duplicated. For children the opposite holds: spawn and resume share one seat path, which is why item 1 holds. `turns.rs` at 5997 lines is fair; F1 is a branch missed inside one 400-line function.

### P3 - Kimi

[model: kimi-code-global (the preset's default model)]
THESIS

A4's real defect is not its size. It is that harnessd has no single owner for its own policies: the mode policy has three doors with three behaviours, the restart-owed policy is written three times in one file, and a child's ceiling is a cell wired at one call site. Size is the symptom; duplicated policy is the fault, and one copy demonstrably loses state.

FINDINGS

1. A point moved through the ask/consent door is never persisted — high.
`Harness::ask_mode_confirm` applies a non-consent point at crates/harnessd/src/harness.rs:933-937; `answer_mode_confirm` applies a consented one at :1054. Neither writes the session row or the project row — `mode_store.set_session` exists only at harness.rs:875, sessions.rs:4945 and modes.rs:296. Reachable: bridge `leticode_mode` → crates/bridge/src/tools.rs `set_mode` → bridge/src/head.rs:2312 `ask_mode` → sessionlog/src/client.rs:529 `mode_confirm`, for *any* mode name, and the answer arriving through sessions.rs:4848.
Scenario: a bridge seat narrows a project stored at `writes allowed` to `read-only`. The daemon applies it in memory and stamps `mode_source = "/mode, this session"` (harness.rs:795); nothing is written and no `mode_unpersisted` warning is said. The daemon restarts; open.rs:670-676 looks for the session's own row, finds none, and the project row wins — the session is back at `writes allowed` and writes again. Fail-open and silent. No test calls `answer_mode_confirm` at all (only its definition and sessions.rs:4848).
Change: move the record into `set_mode_consented` (or make one `Harness::move_mode(mode, consented, source)` that all three doors and the ask path call), so persisting cannot be forgotten by a new door; add a test that reads the session row after each door.

2. Two doors on one verb disagree on atomicity — medium.
sessions.rs:4905-4930 writes rows first and returns `Failed` without moving; turns.rs:3305-3321 (the queued door, `apply_queued_mode` at :3275) moves first and only warns. The same `/mode` typed at an idle session and during a turn produces opposite outcomes when the store write fails. Same fix as 1.

3. Open and reseat do not build the same session — medium.
A child's ceiling is `parent_ceiling` at open.rs:2214-2220, whose value is the child's *own* clamped mode; the parent's live cell is handed over only by children.rs:4114 `follow_parent`. No open path reconstructs it. `within_parent` (harness.rs:813) therefore compares a reopened child against itself. HYP on the restart consequence (position 1 owns that); verified that the ceiling is not a session fact.

4. The hub is a hub — medium, structural.
turns.rs is 5,997 lines and handles submission, restart, outage/fallback, silence watching, abandoned-call sweeps, context claim, queues, mode and model choice; `restart_owed` is taken and re-handed at :472, :695, :737-739 and :779-804 across `wake`, `continue_after_restart` and `restore_after_restart`. open.rs (6,032) has three entry points (`:459`, `:466`, `:1994`) over 31,741 lines of `harness/` plus 13,576 of its own tests. Change: `harness/restart.rs` for the owed path, one open, one mode door.

CONCESSIONS

Position 2 is right about the common path: the TUI's own `/mode` goes through the persisting door (tui/src/app/keys/cards.rs:78-80), clamping and restore work when the invariants hold, and line count alone is not a defect. Position 1 would call 1 and 3 authority bugs; I say the authority is fine and the bookkeeping is not, because three doors each re-implement it — which is why 1 has no test and 2 has two answers.
