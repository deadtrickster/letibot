## Round 1

### Position 1 - GLM
```
[model: glm-coding (the preset's default model)]
THESIS: The plugin trust system gates the wrong half. A pin decides whether a layer's *looks* are adjudicated; nothing decides whether the layer's *answers* are obeyed. Every hook that moves authority — `steer_turn`, `compact_summary`, `limit_decide` — is answered by whatever layer declares it, pinned or not, and repo content reaches three more doors (command files, `.mcp.json`, MCP stdio) with the same shape: one operator act over a *path*, then content-driven execution.

FINDINGS

1. HIGH — Unpinned layers decide control flow. `answering()` (`crates/harnessd/src/plugins/hook.rs:390-403`) filters only `!disabled` + hook name; `steer` (`:224`), `compact` (`:262`) and `limit` (`:289`) never consult `trusted`. Only session-scope `adjudicate_*`/review hooks are refused (`crates/plugins/src/manifest.rs:544-548, 585-613`) and only the `chat` feed needs a pin (`:552-563`). A cloned repo's `.letibot/plugins` layer (Scope::Project, discovered at `crates/plugins/src/admit.rs:53`) therefore: continues turns with repo-authored sentences; chooses what a compaction keeps (`crates/plugin-sdk/src/compact.rs:10` — the record itself); and on a rate limit answers `limit_decide` with `AskUser` posting attacker-chosen question/options on the operator's card (`crates/harnessd/src/harness/limit_hook.rs:186-197`, `limit_ask :289`) or `Switch`/`NewSession` redirecting the whole conversation to another configured provider (`:165-185`). Scenario: clone a repo, hit its 429, the repo's layer "asks" the operator to approve a switch, or silently parks/stops turns. Fix: `admit_for` requires a pin for acting hooks, as it already does for the `chat` feed.

2. HIGH — Repo command files are operator rows. `crates/harnessd/src/commands.rs:42-46` reads `.letibot/commands` and `.claude/commands` from the checkout; `crates/harnessd/src/sessions.rs:1211` runs the body via `run_prompt(..., None, None)` → `Door::Prompt` → `Speaker::Operator` (`crates/harnessd/src/harness/turns.rs:201-202`). R283's `allowed-tools`/`model` narrow the turn, but the row seeds the auth trail as the operator's (I3), and the oracle/automode read it. Fix: run command files as `Speaker::Agent` with a notice.

3. HIGH — `.mcp.json` trust is a path prefix; the server runs unconfined. `mcp_trusts` is `ws.starts_with(t)` (`crates/leticode-config/src/lib.rs:1273-1280`), so one trusted directory trusts every repo and worktree under it. A trusted checkout's relative command resolves inside it (`crates/harnessd/src/mcp.rs:56-58, 62-69`) and is spawned by plain `Command::new` with the daemon's environment, no bwrap, no cleared env (`crates/mcp/src/wire.rs:80-91`). Tool *calls* are Network-gated (`crates/tools/src/builtins/external/mcp.rs:110`), but the server process itself is repo code on the host as the daemon user. Fix: exact-path trust, per-commit or hash, and confine stdio servers like any exec.

4. MEDIUM — A pin exempts `exec` looks entirely. `crates/harnessd/src/plugins/conditions.rs:190-195`: a trusted layer's exec look returns "run it" before the gate; the capability is the program name only, arguments are plugin-chosen per call — a pinned `exec:sh` is an ungated shell whose every invocation is new. Fix: gate argv, not program identity, or expire pins.

5. LOW — `Capability::Http` is a phantom. Declared at `crates/plugins/src/manifest.rs:72`, served by no look (`crates/harnessd/src/plugins/tool.rs:496-533` knows read/list/grep/exec) and granted no import (`crates/plugins-rano/src/lib.rs:43` uses `Capabilities::default()`). Pins record it; when it is implemented, every pinned layer declaring `http:` gains network with no re-pin (`Rebuilt::Kept`). Fix: refuse it at admission until it exists.

CONCESSIONS: no host imports, fuel and memory caps, fresh instance per call (`plugins-rano/src/lib.rs:43`); untrusted layers' looks are adjudicated as the equivalent bash call (`conditions.rs:206-235`); MCP calls are gated; the shadow gate refuses a session's own `adjudicate_*` layer. Position 2 will say pins work for real workloads — true for looks, and precisely not for the four acting doors above. Position 3 will say the 20+ hook kinds are thinly tested; agreed, which is why the trust boundary belongs in the hook-kind list (`manifest.rs:542`), one rule, not per-look.

```

### Position 2 - Claude Fable
```
A10 R1, reviewer 2 (position 2: the containment holds)

THESIS
The wasm and MCP-start boundaries hold as claimed and I verified each in code. The authority a repo layer gets is narrower than position 1 will say. The real gaps are three places where the containment is not applied: read looks, MCP process hygiene, and trust by path instead of by bytes. Paths are under crates/ unless absolute.

VERIFIED HOLDS
- No host imports. plugins-rano/src/lib.rs:43 passes `Capabilities::default()` and ignores `_caps` (:78, :84). rano plugin.rs:299-447 links one import per granted capability, and :606 refuses unknown imports. Position 1's "unimplemented Http" is therefore inert: it only raises the gate class to Network (harnessd/src/plugins/tool.rs:145).
- Fuel 50M, memory 64 MiB, and a fresh Store and instance per call: rano plugin.rs:11, :14, :503-506, :593-600.
- An unpinned layer cannot widen:
  - `on_tool_call` rewrites must shrink, and an `answer` needs a pin (harnessd/src/plugins/hook.rs:525-548).
  - The floor only produces `Raised` or `Trapped` (hook.rs:565-612) and fails closed (plugins/src/stack.rs:137).
  - A session layer never answers the floor or review hooks (stack.rs:1064, manifest.rs:544).
  - Its tools meet the gate on every call (tool.rs:249-254).
  - Exec looks are gated, and for tool looks that holds even when pinned (tool.rs:558; conditions.rs:193 is the only ungated path).
- A steer sentence lands as a notice (`Facts::Steer`, harness/turns.rs:2476), not as operator words, with the budget and interrupt checked by the host (hook.rs:246).
- MCP: `.mcp.json` starts nothing without the user file's `[mcp_projects]` (harnessd/src/mcp.rs:36, read from `leticode_user`). The user table wins a name (:48). Calls are `Access::Network` (tools/src/builtins/external/mcp.rs:110, :304). Results are quarantined (:166). Backoff runs 500 ms to 30 s (mcp/src/lib.rs:60, :292-296).

FINDINGS
1. HIGH - `read:<path>` is honoured for unpinned layers. `look::run` (harnessd/src/plugins/look.rs:89-96) and tool `resolve` (tool.rs:613-626) take roots from the manifest with no `trusted` check. Callers: pane.rs:89, :314, :371 and conditions.rs:140.
   - Scenario: a cloned repo ships `.letibot/plugins/x` with `capabilities = ["read:~/.ssh"]` and a `tool_` hook. The gate sees a Read-class call with harmless arguments. The look returns the key, and the payload goes to the model and the provider.
   - HYP: that the gate admits that Read call unasked.
   - Change: honour `ReadPath` only when `layer.trusted`, and gate each look path otherwise.
2. MEDIUM - MCP stdio servers inherit the daemon's environment and are killed singly. mcp/src/wire.rs:80-90 has no `env_clear` and no process group; `Drop` kills only the direct child (:242).
   - Scenario: an `npx` server reads provider keys from the environment, and its node grandchild outlives the kill.
   - Change: `env_clear` plus an allow-list, own process group, kill the group.
3. MEDIUM - MCP input is unbounded, unlike the wasm side. wire.rs:96-103 uses `lines()` into an unbounded channel that drains only during a request. The SSE `data` buffer at :346-352 is unbounded too.
   - Scenario: a server writes one endless line and the shared daemon runs out of memory, taking every session.
   - Change: cap line length and use a bounded channel.
4. MEDIUM - MCP trust is a path prefix, plugin trust is a hash. leticode-config/src/lib.rs:1273.
   - Scenario: an agent edits a trusted checkout's `.mcp.json`, and the next open execs its command.
   - Change: pin the file's sha256 and report a moved pin.
5. MEDIUM (HYP, not run) - fuel is not wall-clock. Only `consume_fuel` is set (rano plugin.rs:137-139), with no epoch deadline. Bulk memory operations over 64 MiB cost constant fuel. The call holds a per-module mutex shared by all sessions (plugins-rano/src/lib.rs:182, :205).
   - Change: add an epoch deadline.
6. LOW - `limit_decide` `switch` accepts any configured metered model, not only the offered candidates (harness/limit_hook.rs:163-177, turns.rs:3624). An unpinned layer can move a conversation to another provider.
   - Change: restrict to `candidates`, or require a pin.
7. LOW - `Entry::call` holds the link lock across a 60 s call and across reconnect (mcp/src/lib.rs:311-314). The pool is daemon-wide (harnessd/src/mcp.rs:137).

CONCESSIONS
- To position 1: unpinned `steer_turn`, `compact_summary` and `limit_decide` do answer (hook.rs:16-18 has no trust check). Pinned condition exec is ungated (conditions.rs:193). MCP descriptions go verbatim into the tool schema (external/mcp.rs:106).
- To position 3: letibot has no test for the fuel cap, the memory cap, import refusal, or an unpinned layer's reads. plugins-rano's four tests cover the cache and fuel accounting only (:229-303). The cap tests live in rano (plugin.rs:1402, :1422), pinned by rev.

Not run: no tests executed; everything above is from reading.
```

```
THESIS

Scenario: a layer answering three cards for two parts falls to `.ok()` and is silently ignored, or answers `verb: "read"` for a write the head then draws as a read — no test draws a plugin card. Scenario: a layer answering `{"do":"call","function":"x"}` that returns to itself spins inside a turn; the bound is the only stop and no test asserts it. Medium. Scenario: the trust decision at `harness/open.rs:2120-2143` — user table wins a name, untrusted checkout skipped, project `[mcp]` named not started — is proven only per-function, never as a session's tool list. Proposed: one integration test asserting the mounted tool names for trusted/untrusted/`[mcp]` cases.

CONCESSIONS

Trust is well covered (`crates/plugins/src/trust.rs:771-1028`), `push_` likewise (`bridge/src/push.rs`, 14 tests), and each SDK parser has 3-10 tests. This is three named kinds at zero-to-four tests and one authority rule at zero — not a blanket claim.

ANTICIPATION

Position 1 will cite `tests/limits.rs:1518` (`with_limit_hook`), where an unpinned project layer decides the park. I grant it: the tests encode that as intended, so their "authority" claim is a tested design fact. ## Synthesis
```

### Agreed findings

- **F1 HIGH - unpinned layers decide.** `harnessd/src/plugins/hook.rs:16-18` (`answers`) and `:390-403` (`answering`) never read `trusted`. `steer` `:223`, `compact` `:259` and `limit` `:289` act on any enabled layer's answer, and `Stack::run` (`plugins/src/stack.rs:1053-1088`) bans only the floor and review hooks for a session layer (`NOT_A_SESSIONS`, `:140`). A cloned repo's `.letibot/plugins` layer continues turns with its own text, writes into the compaction record, and on a 429 parks, asks the operator its own question (`limit_hook.rs:186-197`), switches provider or forks. Raised by GLM, Opus, DeepSeek R2 and DeepSeek (supplementary) twice. Conceded by Fable. Kimi grants it is the tested design (`tests/limits.rs:1518`), which makes it a design decision, not an accident. Fix: a `DECIDES` list beside `NOT_A_SESSIONS` (`limit_`, `steer_`, `compact_`) that needs a pin, else the fixed ladder.
- **F2 HIGH - MCP stdio servers are unconfined.** `mcp/src/wire.rs:80-91` uses `.envs(env)` without `env_clear`, no process group, no sandbox. `Drop` at `:240-244` kills only the direct child. DeepSeek (supplementary) adds that every other spawn clears the env (`tools/src/exec/host.rs:2305`, `exec/shell.rs:1196`, `exec/term.rs:263`) and provider keys are read from the env (`provider/src/keys.rs:236-240`). All six positions or their supplementary runs name it. Verified at synthesis.
- **F3 - MCP trust is a path prefix.** `leticode-config/src/lib.rs:1271-1281` `mcp_trusts` is `ws.starts_with(t)`. Every worktree under a trusted dir is trusted, and an edit to `.mcp.json` runs at the next open (`harnessd/src/mcp.rs:36-69`, `harness/open.rs:2120-2151`). GLM, Fable, Opus, DeepSeek (supplementary). Severity disputed, see below.
- **F4 MEDIUM - MCP reader is unbounded.** `mcp/src/wire.rs:95-103` `lines()` into an unbounded channel, SSE `data` buffer `:346-357`. Fable, DeepSeek R2, Sonnet.
- **F5 MEDIUM - pinned condition exec is ungated.** `harnessd/src/plugins/conditions.rs:190-195`. The pin covers bytes, not the argv the layer builds per call. GLM, DeepSeek (supplementary), conceded by Fable and DeepSeek R2 (DeepSeek R2 rates it low).
- **F6 MEDIUM - the sandbox boundary is tested in rano, not here.** `plugins-rano/src/lib.rs` has 4 tests (`:229-303`), none for import refusal, fuel trap, memory cap or state carry-over. The cap tests live in rano (`plugin.rs:1402`, `:1422`), pinned by rev. Fable concession, Sonnet.

```
THESIS

Positions 1 and 2 both argue about *what the extension surface decides*; neither notices that the machinery is wrong at three specific points, so the argument over policy is moot until they are fixed. The evidence is not a missing check — it is a check the tree applies everywhere except here, a lock held across a network call, and a trust bit attached to the wrong noun.

FINDINGS

1. The MCP stdio spawn is the one spawn in the tree that inherits the daemon's environment. `crates/mcp/src/wire.rs:80-86` builds `Command::new(command).args(args).envs(env)` with no `env_clear()`, while every other spawn clears and re-states (`tools/src/exec/host.rs:2305`, `tools/src/exec/shell.rs:1196`, `tools/src/exec/term.rs:263`). Provider keys are read from the process env (`provider/src/keys.rs:236-240`), so a third-party server binary — or a checkout's `.mcp.json` command under a `[mcp_projects]` prefix (`harnessd/src/mcp.rs:36-57`, `leticode-config/src/lib.rs:1273`) — receives every token the daemon holds, unconfined, with a writable `cwd`. **high.** Change: `env_clear()` + explicit `env` + `PATH`, plus the same BASH_ENV-style filter `HostProcesses` uses.

2. The MCP call path holds a server-wide mutex across the call and never retires a wedged server. `crates/mcp/src/lib.rs:310-311` takes `Mutex<Link>` and holds it through `client.call` (60 s default, `:23`); there is no deadline on the acquire, so one slow `tools/call` queues every session on that server for N×60 s. A timeout becomes plain `Transport` (`:157-162` sets `dead` only on `Gone`) and `wire.rs:200-220` sends no `notifications/cancelled`, so the server keeps working and the model retries a call that may already have run — double execution with no warning. **high.** Change: per-call id + cancel on timeout, mark timeout-uncertain in the tool result, and either a per-call connection or a queued tokio-style deadline.

3. Trust governs what a layer may *do*, never what it may *decide*. `plugins/src/stack.rs:140-149` restricts exactly three hooks (`adjudicate_floor`, `review_brief`, `review_verdict`) from a session's own layer, and `harnessd/src/plugins/hook.rs:16-18` / `:390-404` (`answers`, `answering`) never read `Layer::trusted`. A project-scope layer is a file in the checkout (`plugins/src/paths.rs:85`), so an unpinned layer answering `limit_decide` (`plugin-sdk/src/limit.rs:11`) parks, switches models or forks the conversation (`harnessd/src/harness/limit_hook.rs:105`), and answers `steer_`/`compact_`. HYP: no test exercises an unpinned steer/compact/limit answer. **high.** Change: a `DECIDES` list beside `NOT_A_SESSIONS` requiring a pin, and `ask` refusing an untrusted layer for those kinds.

Nothing asserts the partition; a prefix added to one and not the other is a hook that silently never fires. **medium.** Change: one const, `SERVED ∪ UNSERVED == PREFIXES` asserted.

5. `RanoModule::call` (`plugins-rano/src/lib.rs:202-210`) holds a mutex across the module call, and a built-in module is shared process-wide by content hash (`:135-162`). Every session's `pane_`, `command_`, `on_tool_call` and `notice_` on that layer serialises behind the others, bounded only by fuel — measured at 33M of 50M for one pane. **medium.**
```
