## Round 1

### Position 1 - Claude opus

Thesis: I22, I23, I25 and I29 are each violated by a concrete path at 9e9312b06. The fault is the same in all four. Liveness is asked late or asked locally. `close_due` fires its two hard triggers before it reads activity. Cleanup asks only this daemon's registry. Remote hosts have no reaper of their own. The backbone also misreads one point: `close_due`'s early return is the operator HOLD (`held_until_ms`, tokencore/src/store/owners.rs:326), not the lease. A head or turn renews only `lease_ms` (owners.rs:573), and the lease only feeds the idle branch.

Findings

1. high, I22/I24. `owner_for_open` copies `created_ms` on resume (crates/tools/src/lifecycle.rs:460). The hard TTL is checked before `starting`, busy and served_by (crates/tools/src/lifecycle/reap.rs:158-164 vs :181). Scenario: a package is reopened by id 25 h after creation (bridge/src/tools.rs:543, harnessd/src/harness/open.rs:1982) and its turn is closed within one SWEEP (60 s). The test `a_hard_ttl_does_not_care_what_the_owner_is_doing` (reap/tests.rs:163) locks this in. d.3 says "since creation or last reopen" (docs/lifecycle.md:585). Fix: stamp `reopened_ms` on resume and measure the TTL from max(created, reopened).

2. high, I22. The parent-closed check (reap.rs:149-157) also comes before busy. A subagent mid-turn dies as soon as its parent row reaches `Closed`, for example through finding 1. Fix: a busy child goes to drain, not close.

3. high, I23. `keep_jobs = !owns_open_job` (reap.rs:717). So the restart marker never keeps the closing owner's own jobs, only other owners' jobs. Then `end_processes` (reap.rs:779) kills every open job of the owner whatever `end_daemon` returned. Any hard-TTL or parent close of an owner with a running job kills that job. Fix: detach to the next daemon, or refuse until the job ends.

4. high, I22/I23/I26 (traced, end state HYP). The daemon for package W is the record whose workspace is W (lifecycle.rs:860). Another daemon gets `served_by` and leaves W alone (reap.rs:181), so only W's own daemon can idle-close it. Its `end_daemon` returns Kept, "never reaps itself" (reap.rs:1175). So `left>=1` (:749) and no `ReapAct::Close` is written. `registry.close_session` never runs (harnessd/src/reap_pass.rs:91-101). The row stays `Closing` while the session is still served. `renew_held` skips non-Live rows (reap_pass.rs:160). Each later pass reruns `end_processes`, so any job that session starts is killed within 60 s. The test `an_attached_head_holds_a_package...` (harnessd/tests/session_lifecycle.rs:973) uses repo "/tmp", which no daemon record matches, so this branch is never exercised. Fix: on a self-owned close, emit Close and let the registry close the session. Add a test whose owner repo equals the daemon's workspace.

5. medium, I22. The head of a landed package does not renew the lease (reap_pass.rs:163). An attached operator head is detached by an idle close.

6. high, I25. `retire_if_empty` (crates/harnessd/src/mergequeue/git.rs:846) proves only "no commits, clean". It then runs `git worktree remove --force` (tools/src/git.rs:344-347). The supersede path asks only `door.session_live`, which is this daemon's registry (mergequeue.rs:416-421, serve.rs:1627). The child path asks nothing (harness/children.rs:3555). Compare `settle_tree`, which calls `in_use::why_kept` (serve.rs:1453). Scenario: a superseded branch's tree is reopened through the bridge in another daemon, or a shell sits in it, and the tree is deleted under it. Fix: call `why_kept` inside `retire_if_empty` itself.

7. medium, I25. `cwd_inside` skips a process whose cwd link cannot be read (in_use.rs:60-62). It also returns None when `/proc` cannot be read (`.ok()?`, :57). Both fail open. A root-owned container or another uid working in the tree is not seen (HYP: gate containers bind-mount trees). Fix: treat an unreadable cwd under a candidate tree as kept, or check open fds through `fuser`.

8. high, I29. The only caller of `host_pass` is the home box's disk half (tools/src/lifecycle/reap/disks.rs:609). It is driven by home-store holdings and runs only in a daemon that holds `DiskTurn`. Nothing is installed on the host. When the home box or its store is gone, the remote compute runs on with no limit. Fix: a host-side timer that runs `reap_script` on `owner.json`.

Concessions
- The disk half runs in one daemon per box (`DiskTurn`), and in_use runs on the settle and sweep paths.
- `DAEMON_GRACE` interrupting a detach stays HYP.

Anticipating position 2 (intended or unreachable): docs/lifecycle.md:604 does accept that the closing owner's job ends on a hard close. ### Position 3 - Claude sonnet

P5 r1, reviewer 3 (position 3). Commit 9e9312b06, paths under crates/.

THESIS
The reaper is wrong by construction. It does not read one fact, "this process tree is owned and alive". It reconstructs liveness from seven loosely coupled inputs held in four stores: store rows, a cgroup, /proc cwd scans and a pid record. Every gap in I22, I25 and I29 is two of those inputs disagreeing, or a caller that asked fewer than all of them. The same predicate exists three times and the copies diverge. The fix is structural: one stamp per process tree, written at spawn and inherited by children, with one liveness query over it. Patching the holes one at a time is what R201, R225, R241, R266 and R307 have each done in turn.

FINDINGS

1. HIGH. Seven inputs decide one yes or no, and they are not read atomically.
`tools/src/lifecycle/reap.rs:146 close_due` reads:
- the owner row (`state`, `held(now)`, `hard_ttl_ms`, `idle_ttl_ms`, `lease_ms`)
- `Activity.busy`, `.parent`, `.daemon`, `.kept`, `.served_by`, `.starting` (`reap.rs:111-129`)
- the kind, which exempts sessions
Their order is itself the policy: parent gone, then TTL, then `starting`, then daemon-gone, then busy, then idle. The first two fire before `busy` is read.
Failure: a package reopened after its TTL is closed at the next pass even with a running job (`now_ms - o.created_ms >= ttl`, `reap.rs:159-163`). The invariants doc cites the same reopen-copies-`created_ms` path at `lifecycle.rs:460`; I did not re-read that line, so that part is HYP.
Change: one `tree_stamp` row per process tree, with the owning daemon's start time and a lease. Busy-ness is the cgroup, as `busy()` (`reap.rs:433`) already does for scopes.

2. HIGH. I25: `retire_if_empty` has no liveness check, and the check it does get is a different one.
- `harnessd/src/mergequeue/git.rs:846` calls `commit_on` and then `retire_branch`, which calls `remove_worktree`. A grep of `git.rs` shows `in_use` appears only in the sweep (`:916-990`), not in `retire_if_empty`.
- The child cleanup `harnessd/src/harness/children.rs:3540-3555` (`retire_an_empty_tree`) calls it with no liveness check at all.
- The queue caller (`mergequeue/serve.rs:1627`) asks `door.session_live`. `session_is_live` (`mergequeue.rs:416`) answers only for this daemon's registry (`registry.get || registry.opening`).
Failure: daemon A serves package P and holds the writer row. Its tree is clean with no commits, which is the normal state before the first edit. The queue in daemon B withdraws a superseded row naming P's branch. `session_live` is false in B, so `retire_if_empty` removes the worktree under A's live session. `why_kept` (`in_use.rs:13`) would have caught it through `writers_under`, but nothing calls it.
Change: make `retire_branch` itself consult `why_kept`. Safety belongs in the destructive primitive, not in each caller's courtesy check.

3. MEDIUM. Another user's cwd is invisible (I25).
`in_use.rs:55-58`: `read_link(cwd)` fails with EACCES for another uid's process and the loop does `continue`. The doc comment calls it "not one of ours". The `live_session` branch only helps if that process is a letibot daemon that wrote a `session_writer` row. A shell or editor of another user in a shared worktree is not seen, so a tree can be removed under it.
Failure: user B has a shell in a tree user A's queue reaps.
Change: treat an unreadable cwd as "kept", the rule d.4 rule 8 already applies to an unreadable store. Or use the stamp from finding 1.

4. MEDIUM. `renew_held` splits "held" three ways.
`harnessd/src/reap_pass.rs:152-170`: head (excluding landed), `turn_in_flight`, and open processes. `busy()` in `reap.rs` uses the cgroup first and the process rows second. The renewer and the judge therefore disagree about what busy means. A job whose supervisor row is stale but whose cgroup is populated is busy to the judge and not renewed. The judge's `served_by` guard makes this mostly safe, but only because a second input patches the first.

5. MEDIUM. I29, remote hosts: there is no host-local reaper.
It is `host_pass` run from the home box over ssh (S17). If the home box is gone the lease never expires on the host. A per-tree stamp with a host-side TTL check fixes this. The seven-input design cannot, because most of its inputs live on the home box.

CONCESSIONS
- The ordering in `close_due` is documented and deliberate. A backstop TTL has to fire regardless of busy-ness, and the code does this.
- `busy()` using the cgroup rather than rows is the right direction. The stamp design extends it.
- `why_kept` is correct as far as it goes, and I27 holds.

ANTICIPATED OBJECTIONS
- Position 1 will list individual violations. Findings 2 and 3 count among them, but I say the whole class recurs for as long as the predicate is scattered, so each is a symptom.
- Position 2 will say the gaps are documented or unreachable. Finding 2 is reachable in normal operation because multiple daemons share one box. The `children.rs:3555` caller has no check, so "documented" does not cover it.
- Both may say a stamp is a big rewrite. The cost is one table and one spawn hook. The reaper already has `holding` rows and a scope handle, so the stamp can be the scope path plus a start time.

Not run: no test. Everything above is from reading.
