THESIS. On the three providers that actually bind this box (GLM/z.ai, Kimi coding plan, deepseek), the limit path is one classification and one decision, and it keeps the turn rather than dropping it: a provider refusal keeps its status, body and `Retry-After` (`crates/turn/src/engine.rs:1296-1320`), one `Policy::class` decides (`crates/http/src/retry.rs:155`), one ladder walks it (`crates/harnessd/src/harness/turns.rs:2949`), and exhaustion lands in `after_the_ladder` (`harness/limit.rs:466`) whose default is `Wait` (`config.rs:1733`). The park is a deadline, not a sleep: it is in `next_idle_at` (`sessions.rs:2747`, `:2755`) so the session's own thread wakes at the reset (`sessions.rs:580`), keeps the daemon alive (`sessions.rs:885`), and resumes the same turn (`take_a_due_park`, `harness/limit.rs:272`). The provider prose is tested, not guessed: GLM's wall clock and window (`http/src/reset.rs:248`), Kimi's hyphenated window (`:311`), GLM's business code ahead of money words (`retry.rs:159`), deepseek's "insufficient balance" as a refusal not a wait (`retry.rs:296-316`). End to end: `harnessd/tests/limits.rs:276, 644, 823, 1040, 1062, 1328, 1365` and the hook at `:1555, 1711`.

FINDINGS (each a real residual of this position).

1. `Retry-After` is truncated to 60 s. `http/src/retry.rs:19` `LONGEST_WAIT`, applied at `:196`, against the doc three lines above that says the provider's instant wins when longer. Severity low. Scenario: GLM 429 with `retry-after: 300`; the ladder retries at 60 s, 120 s, each refusal spending a rung, until the ladder is spent and the park it should have started with is reached late, with the refused calls counted against quota. Change: cap by `reset::LONGEST` (6 h) when a header or `from_prose` named an instant, keeping 60 s only for the guessed rungs.

2. The park is process state. `harness/open.rs:3738` sets `limit_park: None`; nothing in `restart.rs` restores it. Severity low-medium. Scenario: reaper or `--stop` 20 min into a 5 h park; the park and `Probing` (`harness/limit.rs:44`) are gone, `restart::mid_turn` (`restart.rs:491`) sees the stored prompt and opens a turn, which eats one refused request and re-parks — the probe ladder restarts from step 0. Change: persist `(model, until_ms, reset_ms)` on the session row exactly as `set_auto_compact_stood_down` does, restore beside `restore_auto_compact` (`sessions.rs:783`).

3. `pre_emptive_compact` disagrees with `measure_resident`. `config.rs:1584` returns false while `ledger_scale` is None, but `harness/wall.rs:294-306` already converts through `carried_scale` — a pair measured on the model before a switch. Severity medium. Scenario: `/models` from GLM to deepseek in a 180k-token session (128k window): the pre-emptive door stands down for the whole first turn, and the session pays a full refused request before `compact_because_refused` (`wall.rs:412`, `turn_tail.rs:281`) folds. Change: admit `carried_scale` in `pre_emptive_compact`.

4. `limit_hook`'s episode file is per model, not per turn. `harness/limit_hook.rs:14, 37` under `daemon_logs()` (`config.rs:2026`), which falls back to `workspace/.letibot` when `logs_root` is None; two sessions on one workspace then share one map, so an `answered` an operator gave session A can decide session B's episode (HYP for a real daemon, which sets `LETIBOT_DAEMON_LOGS`). Severity low. Change: key the file by session, or refuse the fallback.

CONCESSIONS. `restore_after_restart` + `wall.rs:2052` restore the compaction and the ratio (`open.rs:3562-3585`), and `wall_goes_on` bounds continuations (`turn_tail.rs:186`), so I do not claim an unbounded fold loop. But the refusal door never stands down: a session whose own prefix exceeds the window fails every turn until `/compact` or a wider `--context-window`. And a park longer than `LONGEST` is a re-ask, not a wait.
