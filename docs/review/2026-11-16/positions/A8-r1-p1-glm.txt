FINDINGS

1. HIGH — an fyi that names this seat is "passing" to every push layer. The room crate says a named fyi is `Addressed` (crates/room/src/chat.rs:396); the bridge's private copy says `Fyi => "passing"` unconditionally (crates/bridge/src/rooms.rs:409), and that word is the `event` every `push_channel` layer decides on (crates/bridge/src/push.rs:296-307). The contract promises "the room's own words (letibot_room::Reach)" (crates/plugin-sdk/src/push.rs:29-32; docs/plugin-extension-points-wide.md:896). Scenario: operator sends `fyi` naming `cc@pkg`; the harnessd link rings it; a project layer written "push only `addressed`" answers `push:false`, which `Out::decide` honours (plugin-sdk/src/push.rs:139-151) — Claude Code is never woken, silently. Fix: delete the copy, serialize `Message::reach(..).word()`, and pin a test that the bridge's event equals the room's Reach for one frame.

2. HIGH — two wire changes rode under room protocol 12. `Request/Response::MayPrompt` (crates/room/src/wire.rs:261,657; commit 5e721bbad) and `Hello.share/family` (wire.rs:166-170; cfae85130) were added with `ROOM_PROTOCOL_VERSION` still 12 and the version comment naming only ArchiveRoom (wire.rs:12-15). Scenario A: new bridge, pre-5e721bbad coordinator (both speak 12, so Hello passes): `leticode_send` to an unheld session emits `may_prompt`; the old server reads `ReadFrame::Bad` and *closes the connection* (crates/room/src/server.rs:4516-4525) — the send fails and the stream churns. Scenario B: pre-cfae85130 coordinator silently ignores `family` (no `deny_unknown_fields`), so a suffixed bridge receives no family mail, with no error anywhere. Fix: bump to 13; client-side, gate `may_prompt` on the coordinator's advertised version and treat a Bad-close as a refused frame.

3. MEDIUM — `prompt_once` returns "did not take the prompt in 5s" while the prompt still lands (crates/bridge/src/fleet.rs:186-214): the detached thread keeps waiting for `Accepted` (fleet.rs:229-249). A busy daemon takes >5 s; the tool errors (crates/bridge/src/tools.rs:869-876); the agent retries; the session runs the same text twice. Each timeout also leaks a parked one-shot head (thread + attachment). Fix: cancel on timeout (detach + join) or dedup by a client-minted prompt id at the daemon.

4. MEDIUM — unbounded suffix recursion with a fixed point. On `name_in_use`, `open()` re-calls itself after `set_handle(suffixed(handle(), pid))` (crates/bridge/src/rooms.rs:818-825); `suffixed` truncates to 27 chars then appends `-<pid&0xfff>` (rooms.rs:199-204). For any handle ≥27 chars (easy: `cc@folder:name`) the second suffix is idempotent, so a live suffixed twin with a colliding low-12 pid (~1/4096) means infinite recursion → stack overflow → the bridge dies and its session loses the channel. Fix: bound at two attempts, then fail with the sentence.

5. MEDIUM — the room-waiter shares the *other* folder's name. `rooms::wait` recomputes `handle()` — the base name — and `share_name()`s onto it (rooms.rs:2000,2059). With two folders of one name, bridge A holds `cc@x`; the waiter of session B connects as `cc@x` too; a dm `to: cc@x` is visible by name match (crates/room/src/server.rs:1722-1730) and wakes session B with mail addressed to A, while a dm to `cc@x-8e0` wakes no waiter at all. Fix: persist the settled handle and have the waiter use it, or declare `family`.

6. LOW — a dying old reader takes the new connection's `waiting` slot with no generation check (rooms.rs:1285-1300; `live` *is* guarded), spiking an in-flight round trip into a redial. Fix: same guard.
