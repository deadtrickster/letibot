Thesis. The daemon serves every protocol number (sessionlog/src/server.rs:729-744), but its compat layer translates only one change, `TurnEnded` (sessionlog/src/compat.rs:18-80). The version number also fails to move on some meaning changes. So skew does more than produce loud `Unreadable` notes. It can silently cost an attach, change a prompt's meaning, or kill a session's head. The doc comment says the opposite of what the code does: it says a mismatch is refused (sessionlog/src/protocol.rs:12-14).

Findings

1. HIGH. The session socket reads lines with no length bound, and it does so before the peer check. `FrameReader::read` calls `read_line` into a `String` with no cap (sessionlog/src/wire.rs:62). `serve_conn_rooted` reads the first frame at server.rs:712, and the inside-peer refusal only comes at :742. Inside peers can reach the socket by design, because of askpass (sessionlog/src/peer.rs:7,14). Scenario: a model tool call writes several GB to the socket with no newline. The daemon's memory grows until it is killed, along with every session it serves. That the socket path is reachable from a confined tool is HYP, but the peer code assumes it is. Fix: bound the read with `take(MAX+1)` and refuse an over-long line, the way room/src/server.rs:4992-5002 already does.

2. HIGH. The daemon accepts heads that it knows cannot decode its `Hello`. The history string in protocol/tests.rs says version 75 `TurnState::Parked` moved the number because "an older head cannot decode a snapshot that carries it". `TurnState` is internally tagged (sessionlog/src/view.rs:169), and compat.rs has no arm for `Parked`. The `Hello` carries the snapshot (server.rs:2211). The head's pump turns a `Malformed` line into `Unreadable` and keeps going (sessionlog/src/client.rs:1066). Scenario: a v74 TUI attaches to a v78 daemon while a turn is parked on a usage limit. The `Hello` is skipped and the head never seats. The exact TUI symptom is HYP. Fix: add `OLDEST_HEAD` (75), mirroring the room's `OLDEST_CLIENT` (room/src/wire.rs:19), and send `Bye` naming both builds below it. Also: any bump with no compat arm raises the floor.

3. MEDIUM. Meaning changed under one number. 6f538d24a added `Prompt.delivery` (protocol.rs:657) at 76, after 8d4943a7a had already bumped to 76. An earlier 76 daemon drops the field, because there is no `deny_unknown_fields`, so the prompt defaults to `Steer`. The numbers match, so `protocol_skew` returns `None` (protocol.rs:246) and the TUI stays read-write. Scenario: the operator presses Tab to queue (tui/src/app/composer.rs:243). The prompt is injected into the running turn instead, and nothing is said. Fix: bump when a field's absence changes behaviour. Better, put new semantics in `Caps.features`, have the daemon echo the accepted set in `Hello`, and have the head send `Queue` only when it was echoed.

4. MEDIUM. The bridge does not gate on the version it records. `driver_todos` (bridge/src/head.rs:2252, called from bridge/src/tools.rs:893) sends `DriverTodos` without checking `daemon_protocol >= 77`. A v76 daemon fails to read it and answers `Bye` (server.rs:2146-2157). Scenario: `leticode_todo` against an older daemon closes the held head of a live package. `fleet::prompt_through` ignores the `Hello` version entirely (bridge/src/fleet.rs:216). Fix: check the version before sending each frame, and return a refusal to the tool instead of dropping the socket.

5. MEDIUM. A skipped event is acknowledged anyway. The bridge advances `seq = max(env.seq)` on every readable event (bridge/src/head.rs:836). rano does the same with `fetch_max` (~/Projects/rano/rano/src/letibot.rs:909). An unreadable line has no seq, so the next readable event acknowledges past the lost one, and it is never redelivered. Fix: on `Unreadable`, hold the ack or send `Resync`.

6. LOW-MEDIUM. The room protocol has stayed at 12 while it changed. `MayPrompt` (room/src/wire.rs:261) and Hello `family` (:167) were both added under 12 (5e721bbad, cfae85130). An older 12 coordinator closes the connection on `may_prompt`, and it drops `family` silently. Scenario: a new bridge on an old coordinator loses all family mail and says nothing. Fix: go to 13 and keep `OLDEST_CLIENT=11`. That way the old coordinator refuses by name (wire.rs:24).

7. LOW. Drift. rano still declares 72 (~/Projects/rano/rano/src/letibot.rs:26), six versions behind, and nothing tolerates it explicitly. The doc comment at protocol.rs:12-14 and the release comments in the workspace `Cargo.toml` both say "refuse".

Concessions. The room wire caps lines at 1 MiB. The `TurnEnded` compat is correct for rano and other heads older than 76. The TUI goes read-only against an older daemon. rano's loosely typed parser does survive unknown tags. Fields marked `serde(default)` (such as 78's `ran_ms`/`decision`) are genuinely additive.

Against P2 (accept-and-say). Saying the skew is only safe if every accepted version can be decoded and keeps the same meaning. Findings 2 and 3 show that this fails today. A floor plus an echo of features keeps a mixed fleet working and removes the silent cases. Saying is not enough when the session that is wrong never seats.

Against P3 (golden frames). Golden frames would catch 2 and 3, so add them. But both defects can already be proven from the code, and the floor is cheaper and closes them now. Golden frames do nothing for 1, 4 or 5.

I ran no tests. Everything above comes from reading the code at 9e9312b06.
