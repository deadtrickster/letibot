Thesis. Position 2 holds for the failures that actually bit: a session closed under a live head, a worktree removed under a live session, a job lost across a restart, a restart notice dropped. Each has one mechanism and a test. But the mechanism is a lease renewal plus a proof-and-keep closure, and each guard I cannot cite is a real hole. Two are high.

F1 (critical). The hard TTL clocks from `created_ms`, which a reopen deliberately preserves (`crates/tools/src/lifecycle.rs:459-460`, `crates/tokencore/src/store/owners.rs:593-598`), and it is evaluated before `starting` and before `busy` (`crates/tools/src/lifecycle/reap.rs:159-168` vs `:169`, `:181`). Failure: a package resumed after 24h from its first creation (`PACKAGE_HARD_TTL_MS`, `lifecycle.rs:433`) is set `Closing` on the next sweep (≤60s) while a turn is in flight; `reap_compute` then ends its scope and daemon (`reap.rs:656`, `:707-718`). Every reopen re-arms it, so the id is permanently unusable. Fix: stamp a `live_since_ms` at each return to `live` (`owner_for_open`, `reopen_owner`) and measure the hard TTL from it; keep `created_ms` as the record.

F2 (high). `retire_if_empty` (`crates/harnessd/src/mergequeue/git.rs:846-863`) removes a superseded branch's worktree and deletes the branch on commit proof alone — no `in_use::why_kept`, no cwd check — while `settle_tree` (`serve.rs:1455-1471`) and `reap_worktrees` (`serve.rs:1300-1302`) both ask. Failure: a clean, superseded tree is an operator shell's cwd or a second daemon's session; it is removed and the ref deleted. `TODO.md:5440` admits it as "Left". Fix: thread the `in_use` closure into `retire_if_empty` and skip-and-say.

F3 (medium). `why_kept`'s cwd half reads only this box's `/proc` (`crates/tools/src/lifecycle/in_use.rs:57-77`). A seat's own `bash` runs inside bwrap's PID namespace, so no host process has a cwd inside the tree: the guard misses exactly the processes a seat creates. HYP on bwrap's outer cwd; the code path is not. Fix: have the seat write a per-worktree pid stamp, and check it here.

F4 (low). Plan and executor disagree: `judge` (`crates/tools/src/lifecycle/plan.rs:746-773`) says `Now` for a settled owner's Work without asking `in_use`, while `crates/tools/src/lifecycle/work.rs:205` keeps it. `gc --plan` therefore tells an operator a live tree may go. Fix: inject the in_use closure into `judge`.

Concessions. `renew_held` (`crates/harnessd/src/reap_pass.rs:149-171`) is the real answer to "closed under an attached head": lease in `shared.db`, renewed for a head, a turn or an open job. `served_by` (`reap.rs:181`, `:387-392`) keys daemon records on the owner's own workspace (`harness/open.rs:1986`), so a package's dedicated daemon is found, and `crates/tools/src/lifecycle/reap/tests.rs:598` asserts it. Kept jobs are a `DETACHED_JOB` holding that outlives the daemon (`reap.rs:377-380`, `plan.rs:585`). R313 marks delivery only inside the store callback (`turns.rs:695`, `:800`) and splices the handles back when the door does not open (`:737-739`, `:804`). Archive-before-delete is the executor's order (`work.rs:205→211`, `worktree.rs:253-272`). But F1 shows the hard TTL is a bound on row age, not on work, and it fires first — so "whatever it is doing" is the design, and the design is wrong for a resumed owner.

Positions 1 and 3. Position 1 gets F1 and F2 and should take them; its other three claims it cannot make: interactive sessions are excluded from every closing rule (`reap.rs:159`, `:172`, `:184`), a daemon's own attached head renews, and remote owners are leased by `remote.rs:315-441`. Position 3 gets most of F3/F4, but both fixes are closure injections, not a redesign of the seven inputs.
