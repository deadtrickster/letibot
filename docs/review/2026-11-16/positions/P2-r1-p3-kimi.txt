Thesis: R251 added downstream labels, but never established authenticated provenance. `Prompt.from`, `Attach.identity/kind`, and `Caps.can_decide` are client assertions; absent speaker defaults to Operator. Consequently, both “R251 closed the paths” and “fix the remaining producers” miss the root defect: authority must be server-derived from an authenticated connection, with agent/read-only as the default.

Findings

1. Critical — the Claude Code agent can approve its own permission cards. `Head::attach` selects `can_decide=true` (`crates/bridge/src/head.rs:1623-1652`); the daemon trusts that client capability (`crates/sessionlog/src/hub.rs:1735-1736,1777-1785`). The documented `leticode_answer` accepts permission options (`crates/bridge/src/tools.rs:1673-1686`), and every such answer is recorded as `human:<identity>` (`crates/harnessd/src/answers.rs:936-954`). Failure: prompt injection in a repository tells Claude Code to call `leticode_asks`, then `leticode_answer allow_session`; the gated command runs and the corpus falsely records human consent. Change: remove permission answering from agent principals; derive `can_decide` server-side, not from `Caps`. Merely blacklisting `letibot-mcp` is insufficient because attach identity and kind are client strings (`crates/sessionlog/src/server.rs:712-720`).

2. Critical — escaping process classification exposes an ungated operator shell. A known PID is “inside” only through ancestry or a daemon cgroup/process group (`crates/sessionlog/src/peer.rs:47-51,225-256,285-295`); every other connection retains its requested capabilities (`crates/sessionlog/src/server.rs:2185-2192`). It may submit `OperatorShell` (`crates/sessionlog/src/server.rs:1439-1470`), whose execution explicitly has no gate (`crates/harnessd/src/harness/opshell.rs:155-167`). Failure: a macOS tool double-forks and calls `setsid`, defeating both checks—the source itself notes that `setsid` leaves the recorded group—then connects and submits `! <command>`, escaping confinement without a card. Change: operator authority requires a daemon-issued, unforgeable connection credential; default every unattested connection to agent/read-only and deny `OperatorShell`, mode changes, answers, and operator calls.

3. High — missing provenance becomes durable operator authority. `Speaker` defaults to Operator, including deserialised `User` rows (`crates/transcript/src/lib.rs:47-53,144-150`), and resume seeds those rows directly into the authorisation trail (`crates/harnessd/src/harness/trail.rs:104-150`). Internal doors repeat the mistake: a parent-model brief calls `submit` (`crates/harnessd/src/harness/children.rs:4219-4224`), and repository command bodies use `peer=None` (`crates/harnessd/src/sessions.rs:1183-1211`). Failure: an old agent row, malicious subagent brief, or cloned `.claude/commands` body becomes citable operator evidence after restart; the shadow likewise labels it human (`crates/harnessd/src/shadow/feed.rs:49-58`). Change: add non-authorising `Unknown`, default missing provenance to it, migrate legacy rows conservatively, and require explicit server-owned provenance at every submission door.

Concessions: Position 2 is right that truthful `Peer` rows are mapped to non-authorising Agent context (`crates/harnessd/src/harness/turns.rs:258-265`; `trail.rs:137-142`), and unknown PIDs fail closed. Position 1’s producer-specific findings are real. Neither downstream filtering nor call-site patches authenticate the connection, however; the bridge’s current permission-answer path directly contradicts the claim that only the operator authorises.
