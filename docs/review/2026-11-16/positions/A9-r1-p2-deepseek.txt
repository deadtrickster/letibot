Thesis: the three legs are real but unequal. Coordinates are read out of the drawn frame, and one binding table is walked across every surface — so "does it draw what it says" is answered by tests, not by reading 116k lines. But the walk's index is hand-kept, its classification is borrowed from the code under test, its rows are mostly empty, and the width ladder covers one widget.

F1 — `Surface::ALL` is a hand-maintained array (surface.rs:80, 19 entries) and nothing ties it to the enum's variants. Every `match self` (is_list bindings.rs:644, key_name, parent, short_name) is exhaustive and so forces an arm; the array is not a match, so a new `Surface::Fleet` compiles with `ALL` unchanged. Failure: a pane added by the next change is silently outside `every_pane_keeps_the_verb_table` (tests/bindings.rs:402), the wheel walk (settings.rs:1982), the bar/help walk (tests/bindings.rs:83) and the `[keys]` refusal list (bindings.rs:1085) — and the comment at settings.rs:1979 claims the opposite. Change: replace the literal with `fn next_in_all(self) -> Surface` written as a `match self` cycle, plus a test that walking it from `Help` visits 19 distinct surfaces and returns — a new variant then fails to compile until it joins the ring.

F2 — `is_list()` is both the rule and the test's filter (tests/bindings.rs:410, :453), so a list pane misclassified as a reading surface is asserted against nothing, and the test cannot notice because it asks the same function. Change: put the reading surfaces in the test (`matches!(s, Help|Stats|TodoRow|QueueEntry|SubOut|JobOut|PluginDetail)`) and assert `is_list` equals that complement.

F3 — the recorded hit's left edge is unverified on exactly the list panes. `click_on` fixes `x: 12` (hits.rs:17-20), and the pane tests fix 10, 6, 4 (askedcard.rs:146, payloadwindow.rs:336, one_line_walls.rs:105). Only markerclick.rs:121, livecall.rs:113, plugin_pane.rs:114 and linkclick.rs:46 read x off the frame. Failure: a hit rect shifted two columns by a gutter change still contains x=12, so `a_click_on_each_pane_selects_the_row_drawn_under_it` (hits.rs:53) stays green while a click on the row's first cell hits the border and does nothing. Change: derive x from the frame in those four pane cases, and add a property over every frame drawn in the suite — each hit's rect inside the terminal and inside its surface's rect.

F4 — the fit ladder is the transcript marker's alone (MARKER_LADDER markers.rs:495, `marker_room` :452, test transcript.rs:5610). Narrow-width checks are hand-written per widget (jobcard.rs:264, reviewcard.rs:298). Failure: a new pane's row is three columns too wide at 40 and no test draws it. Change: extend settings.rs:1982 into `every_surface_fits_at_every_rung`, drawing each surface at 30/40/50/80/110 and asserting every row's visible width.

Concessions: horizontal verification does exist where the frame is text-dense, and editor.rs:798 covers the split column — F3 is a gap, not a hole. Nothing here reaches position 1's class: a row the model was never sent still renders and still clicks, because the click facts prove frame↔head, never frame↔wire; a drawn-row/wire-row count property is the missing test. The marker's overflow below twelve columns is documented behaviour (markers.rs:576). F1-F4 are coverage defects, no product bug — hence medium at most, and F1 is high only because it disables the other three.

Against position 3: these walks are the one thing that scales — the coupling cost lands in `rano::agent::keys::SHARED` (tests/bindings.rs:425), where a rano bump changes what the editor leg walks without any letibot test noticing. Against position 1: my legs say the frame is consistent with itself; they cannot say it is faithful to the record.
