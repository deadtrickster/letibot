P4 R1, reviewer 2 (position 2: the store makes loss practically impossible). No test run; all by reading at 9e9312b06.

THESIS
A committed row cannot be lost. What can be lost is a row not yet committed, and the fixes are small. Position 1 is right about windows, wrong about the store.

What holds (verified):
- Every writing connection takes WAL + synchronous=FULL (tokencore/src/store.rs:1605-1611). Only embeddings/metrics use NORMAL (embeddings/src/cache.rs:95, metrics/src/store.rs:213); neither holds conversation.
- UPDATE/DELETE on transcript_item abort, INSERT must be next seq (store.rs:527-541). Appends are BEGIN IMMEDIATE, one commit per 64-row chunk (store.rs:3120, 4343-4354).
- No migration arm touches transcript rows: the only DELETE in migrate_from is the v23 queue clear (store.rs:2341). A half-run migration costs availability, not rows.
- The single trigger drop on a live file (tokencore/src/migrate_split.rs:313-317) is inside one transaction, after verify_chains (:274), restored at :352.
- Busy store: persist waits 30 min, resyncs `persisted` from the store (harnessd/src/harness/turns.rs:4480, open.rs:391).

FINDINGS

1. HIGH - prompt leaves the journal before the transcript holds it. pop_front syncs at once (sessionlog/src/hub.rs:481-485, 528-537); the row is stored only at harnessd/src/harness/turns.rs:1713. In between: reseat, render, and a persist that can wait 30 min. Scenario: store busy, operator restarts the daemon; prompt is in neither queued_prompts nor transcript_item. Head re-send: HYP. Change: keep the popped prompt journaled as in-flight; remove it in the `opened` callback, dedupe on client_request_id at restore.

2. HIGH - "stored" is marked when nothing was stored. On a queued interrupt during a busy wait persist_rows returns Ok with rows unwritten (turns.rs:4507, 61-66). submit_items_then then calls opened (turns.rs:1713-1714) -> the_batch_stored -> watch.stored + room ack_through (harness.rs:1404-1408, harness/deliveries.rs:1051-1057). Scenario: Esc during busy store, then restart: job result and room lines acked, row never written, never told again. Breaks R313/I53. Change: return a not-stored outcome on Leave; call opened only when persisted == rows.len().

3. MEDIUM - journal is acked before saved, never awaited. sync() only sends (hub.rs:528-537); journal_settled has no non-test caller (hub.rs:809; only harnessd/src/restart.rs:2066,2078 tests). Scenario: prompt accepted, daemon killed within the fsync. Change: wait journal_settled (bounded) before acking and on close.

4. MEDIUM - room board file can be wiped by one bad byte. Store::open uses read_to_string(...).unwrap_or_default() (room/src/store.rs:92): invalid UTF-8 or EIO reads as an empty store; bytes=0, and after 64 KiB of appends compact rewrites the file from that shadow (room/src/store.rs:373-378, 414-416). Same path makes a skipped line (:122-126) permanent. The closed reader already uses from_utf8_lossy (:306-307). Change: lossy read; refuse to compact after a load that failed or skipped; keep the old file as .bad.

5. LOW - room store never fsyncs (append :353-357, compact :416). Process crash safe; power loss loses recent board rows and can leave an empty file after rename. Change: sync_data on append, fsync tmp + dir on compact.

6. LOW - show before store (turn/src/engine.rs:487 vs turns.rs:1713). Real, but only harms through 1 and 2; with those fixed the loser is a drawn row whose prompt comes back from the journal.

CONCESSIONS
- "Practically impossible" is false for accepted-but-uncommitted input: 1-3 are plain process-death windows, no power loss needed. Position 1 wins there.
- Journal drops `from` (hub.rs:458-470, 779): a restored bridge prompt changes speaker. Not loss, but the record is altered.
- Split set: rows and context are two commits (store.rs:3162-3176); crash between leaves stale context counters, not lost rows.
- Position 3: nothing I verified stops an operator-only row; triggers guard row survival, not row meaning. Out of my position's reach, not refuted.
- Carve claim check is check-then-act against a daemon starting mid-carve: HYP, not traced.
