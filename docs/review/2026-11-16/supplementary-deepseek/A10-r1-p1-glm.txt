**Thesis.** The plugin/MCP surfaces do what they claim for *answers that can only narrow* (the gate floor, `on_tool_call`'s refuse) and fail for everything that can *act or speak*. A project-scope layer and a checkout's `.mcp.json` are both "untrusted repo content", and both get authority the operator never gave: the first decides the turn, the second runs a process. Nothing here needs a pin, a card, or a turn in flight.

**Findings**

1. **A checkout's `.mcp.json` starts an unconfined process, before any gate — critical.** `mcp_trusts` is a path prefix (`ws.starts_with(t)`, `leticode-config/src/lib.rs:1273-1281`), `harnessd/src/mcp.rs:36,47,56` accepts a relative `command` from that file, and `harnessd/src/harness/open.rs:2122-2138` starts the pool at open. `mcp/src/wire.rs:80-91` spawns with `Command::new`, `.envs(env)` — additive, the daemon's env is inherited — and no seat, no bwrap, no cwd restriction beyond the spec. A PR's or an agent's own `.mcp.json` in `<project>/worktrees/wt-x` (under the trusted dir) makes the next child or reopened session run `sh -c …` as the operator, with every key in the env, before a single row. Change: spawn stdio servers through the exec backend (seat plus cleared env) and trust the file by content hash, not by directory.

2. **An unpinned project layer decides the limit — high.** `PluginHost::answers` (`harnessd/src/plugins/hook.rs:16-18`) has no trust check; only `free_layer` (`:10`) does. `admit_for` (`plugins/src/manifest.rs:542-565`) refuses `adjudicate_floor`/review hooks for `Scope::Session` alone, and `stack.rs:52` states the intent: an untrusted layer still answers. So a repo's `.letibot/plugins` (discovered at the workspace, `stack.rs:335`; `PluginHost::for_child(…, &workspace, …)`, `sessions.rs:2262`) answers `limit_decide`. Answering `new_session` reaches `limit_hook.rs:180-185` → `fork_into_new_session`, which writes `parent_session_id: None` and origin `operator` (`tokencore/src/store.rs:2880`) — the conversation continues outside R306's ceiling, its tree's caps and its grants. Change: make `answers` require `trusted` for the deciding prefixes (`limit_`, `steer_`, `compact_`, `command_`), and carry the source's parent into a fork.

3. **A repo's command file becomes the operator's words — high.** `sessions.rs:1211` calls `run_prompt(…, None)`; `peer: None` is `Speaker::Operator` (`harness/turns.rs:202,292`), and `tools/src/authorise.rs:19-21` says only that speaker authorises. A PR adding `.claude/commands/fix.md` with "run the migration, don't ask" puts that sentence in the trail an oracle or the head reads, citable by an ALLOW; the shadow sees `Author::Operator`. `/skills NAME` has the same door (`harness.rs:1539`). Change: a third source on `Utterance` (`Command`), non-authorising and drawn as such.

4. **A pinned layer's exec runs with no card — medium.** `plugins/conditions.rs:190-195` returns "run it" when the answering layer is pinned. The pin covers bytes, not the argv the layer builds from tool output it read. Change: keep the capability check, always pass through `gate.admit_unasked`, and let a permission rule, not the pin, preapprove.

5. **`Http` is an access class with no implementation — low.** `plugins/tool.rs:142-150` gives a layer declaring `http:` `Access::Network`; no look reaches it, so the class is a claim the host never verifies.

**Concessions.** The floor genuinely cannot admit (`adjudicate.rs:116-130`: `Raised` merges through `Tier::strictest`, `Trapped` is strictest), and masking text under `answer` needs a pin (`hook.rs:540-549`). MCP *calls* are gated as Network (`adjudicate.rs:3887`), a project `leticode.toml`'s `[mcp]` is refused (`open.rs:2136-2151`), and `switch` lands only on a configured metered door (`harness/turns.rs:3623`). Position 2 will cite these; they bound the damage, not the authority. Position 3 will say the surface has 1-4 tests per kind — agreeing with that makes 1 and 2 worse, not better.
