**Thesis.** Both other positions argue about instances. The mechanism is the defect: letibot has no test-environment contract at all, so isolation is re-derived by hand in every fixture, while four config resolvers answer the same question differently. The queue's gate and an agent's own `cargo test` still run in the operator's environment, so no amount of per-test patching closes I18.

**Findings**

1. **High — the queue's gate inherits the daemon's whole environment.** `crates/harnessd/src/mergequeue/gate.rs:474-480` (`StepEnv::apply`) sets only `CARGO_TARGET_DIR`, `TMPDIR`, `CARGO_BUILD_JOBS`. The landing step is the project's own line (`AGENTS.md:77`, `cargo test --workspace --no-fail-fast`) and runs with the daemon's `HOME`, `XDG_*` and store vars. `scripts/gate-at.sh:54-55` moves `HOME`/XDG for the *same* step in the *same* repository, and `:39-42` symlinks the operator's real `keys`, `hosts.toml` and `known_hosts` into it. Failure: any test that forgets `XDG_DATA_HOME` writes `~/.local/share/letibot/sessions.db` from the queue's gate; the `LEAKED:` check at `gate-at.sh:57` has no counterpart in the queue. A branch is green under one gate and red under the other for reasons that are the box. Change: `StepEnv::apply` must clear and restate the environment (`HOME`, the four XDG vars, `LETIBOT_*` doors) exactly as `gate-at.sh` does, from one shared definition.

2. **High — an agent's `cargo test` is not a test run.** `crates/harnessd/src/harness/open.rs:1367-1373` puts `LETIBOT_SOCKET`, `LETIBOT_SESSION` and `HOME` on every command a session spawns, so a test binary started by a session resolves the *live* daemon (`bridge/src/daemon.rs:219` per S13) and the operator's config. Change: strip those three in the same helper, at spawn, for `cargo`.

3. **Medium — no helper, so five fixtures, five variable sets.** `crates/bridge/tests/push_events.rs:59-64` sets four vars and no `HOME`; `mode_consent.rs:72-75` sets `HOME` and no runtime dir; `placement.rs:64-69` a third subset; `crates/letibot/tests/gc.rs:117-121` and `no_hang.rs:29-33` use `env_clear` with different restatements. Nothing anywhere clears `LETIBOT_PERMISSION`, `LETIBOT_GC_SETTINGS`, `LETIBOT_NOTES_REPO` or `LETIBOT_LOGS_ROOT` (26 `remove_var` sites across seven names). Failure: the operator exports `LETIBOT_PERMISSION` to test a rules edit; every in-process gate test then adjudicates against that file, silently. Worse, the race locks are per module: seven `static ENV: Mutex<()>` (`bridge/src/plugins.rs:290`, `harnessd/tests/gate_host.rs:14`, `plugins/src/trust.rs:1172`, `tools/tests/confine.rs:37`, `harnessd/src/room/coordinator.rs:339`, `tui/src/app/sessions_pane.rs:1606`, `tools/src/builtins/intent/board.rs:741`) prevent a collision only inside one file, so `set_var` is still unsound at binary level.

4. **Medium — the resolvers disagree, and the disagreement is reachable.** `crates/plugins/src/paths.rs:36-43` treats empty `XDG_CONFIG_HOME` as unset; `crates/provider/src/keys.rs:194-201`, `harnessd/src/modes.rs:40-45` and `tools/src/permission.rs:672-679` map `""` to `PathBuf::new()` — a *cwd-relative* `letibot/providers.toml`. `crates/bridge/src/plugins.rs:289-312` deliberately constructs that state. Failure: with `XDG_CONFIG_HOME=` exported, key resolution reads `$PWD/letibot/providers.toml`, whose `url` (`keys.rs:227`) redirects the provider and the env-supplied key to that host — repo content choosing where the operator's credential goes. Per XDG a relative base must be *ignored*, not used. Change: one `config_dir()`; the other three call it.

5. **Medium-low — isolation is defeated from the product side.** `crates/tokencore/src/apparatus.rs:34-35,20-25` fall back to the literal `/home/dead/models/...`. A test that moved `HOME` still claims the apparatus is present and reads six gigabytes from the operator's home; the same test is red on any other machine.

6. **Low — the guard is a grep.** `scripts/check-test-attrs.sh:47-52` matches `remove_var("LETIBOT_REQUIRE_(APPARATUS|MODEL)")` only; `set_var("LETIBOT_REQUIRE_APPARATUS", "0")` (off, `apparatus.rs:55-57`) or a name held in a constant passes.

**Concessions.** Position 1's instances are real and I do not need them. Position 2's `f3fddd6b4`/`e6cafa02f` fixed daemon-*spawning* tests only; the queue's gate and agent-run cargo were untouched, and `gate-at.sh` proves the fix by grepping its own log for `sessions.db`, not by denying the path. Both will say the gaps are few; six edits each.
