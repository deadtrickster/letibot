Thesis: P2's disagreements are cosmetic. R251 taught the code a vocabulary (`Speaker::{Operator,Agent,Peer}`) but kept Operator as both the serde default and the fall-through for "not classified", so authority is still minted by whoever inserts the text — and `Peer` is consulted only as a deny-list on the wrong side of the seam.

1. **CRITICAL — operator authority is `!inside`, not "is the operator".** `crates/sessionlog/src/peer.rs:30` returns `None` (no door refused) whenever `!self.inside`; `inside` is `descended_from || in_daemon_tree` (`:47`, `:97`). So any same-uid process the daemon did not spawn is the operator. `server.rs:747` blocks a tool tree from attaching; nothing blocks anything else. Scenario, verified by predicate not by run: session A's bash runs in cgroup `letibot.<A>.n` (`tools/src/exec/scope.rs:944`); the box runs one daemon per folder (AGENTS.md); A's tool connects to daemon B's socket — 0600, same uid — `inside` is false against B's pid, and the tool now holds `OperatorCall`, `Stop`, `Mode`, `Answer`. Change: replace the boolean with a resolved principal (`Operator{terminal}`, `Head{identity}`, `Tool`) and refuse any frame whose principal is `Unknown`, instead of admitting it.

2. **CRITICAL — the decision card is opened to any attacher.** `Caps::can_decide` is client-declared and defaults `true` (`sessionlog/src/protocol.rs:314-347`); `Hub::submit` checks only that flag (`hub.rs:1755-1775`) before settling a permission. Combined with finding 1, a process outside the cgroup answers the gate for a session it does not hold. Change: derive `can_decide` from the principal, never from `Attach`.

3. **HIGH — identity is a string any client can claim, and claiming nothing is the dangerous direction.** `Prompt.from: Option<String>` with `None` = operator (`hub.rs:87-94`); `identity == MCP_IDENTITY` (`hub.rs:93`, `origin.rs:10`, `bridge/src/head.rs:1691`) is the only corroboration in the tree. A bridge that reconnects without its identity — older build, restart, a new non-terminal head — silently becomes the operator, with no Unknown state to land in. Change: `Attach` carries a claimed identity; the daemon corroborates it from the peer pid (`/proc/<pid>/exe`, or a token it minted when it spawned the head) and refuses a claim it cannot check.

4. **HIGH — the daemon itself mints Operator where the real speaker is the model.** `children.rs:4223` `h.submit(&brief)` → `turns.rs:201-202` `Speaker::Operator`; a parent's brief is the child's first trail utterance and authorises the child's tools. `sessions.rs:1211` puts a cloned repo's command files out as operator prompts. Both survive because the default is `#[default] Operator` (`transcript/src/lib.rs:49-56`) and the reseed reads every pre-field row as Operator (`trail.rs:103-140`). The steering door repeats it: `hub_io.rs:210-225` is `Agent` iff `peer.is_some()`, else Operator. Change: one `Harness::say(principal, text)` and no `submit()` that assumes a person.

5. **MEDIUM — peer handles are unauthenticated.** `from` is a free string bound to no connection, so a peer can sign `cc@rano` or another session's handle into the rooms and the transcript (`transcript/src/lib.rs:86-102`). Change: prefix-resolve handles against attached seats.

Concessions: the peer door does stop a tool tree, and `submit_with_context_from` (`turns.rs:243-265`) genuinely records `Agent` — R251 is not a no-op. My fix needs a credential the daemon can check, which this tree does not yet have, and no daemon-side rule defeats a `tmux send-keys` into a real head (I4).

Against position 1: six doors in six rounds is whack-a-mole; enumerate principals once. Against position 2: "closed the paths in use" concedes the default — `children.rs:4223` is unchanged.
