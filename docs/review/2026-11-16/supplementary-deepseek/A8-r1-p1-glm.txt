[model: deepseek/deepseek-flash (the default; the one-shot ignored --model)]
THESIS: position 1. The bridge and rooms deliver mail correctly on the paths the tests use and lose or misreport it on the paths nobody tests: the newest verb (`wait-queue`), the second bridge in a folder (the `family` mechanism), and the `push_channel` seam. Each failure is silent, and each is in code added under an unchanged room protocol number.

FINDINGS

1. `wait-queue` reports the wrong ending for a branch that moved. `crates/bridge/src/queue_desk.rs:278` resolves the review row once, `:291` polls only that id, and `:252` maps `MergeState::Moved` to "still in line". Approval followed by a push ends that landing `moved` and opens a new review (`:104-113`). The waiter then spins to its deadline while the branch's real review lands or goes red, exiting 30 (TIMEOUT) with the stale row on stdout — contradicting the exit contract at `crates/bridge/src/main.rs:54-57` and its own doc at `queue_desk.rs:265-267`. An agent reading "still in line" re-enqueues or abandons a landed branch. Severity high. Fix: on `Moved`, re-resolve the newest review of that branch and keep waiting.

2. A second bridge in a long-named folder is deaf to its own name. `suffixed()` (`crates/bridge/src/rooms.rs:199-203`) keeps only 27 chars of the whole handle before appending `-<hex>`, so `cc@letibot-review-snapshot:letibot` becomes `cc@letibot-review-snapshot:-1a2b`. The coordinator validates the family by literal prefix (`crates/room/src/server.rs:26-35`), so `family_of` returns `None` and drops it — the exact case the feature exists for (two bridges in one folder, `docs/room.md:947-952`). The suffixed bridge's name is now `-1a2b`: it is in the room, takes suffixes, and never hears `cc@<folder>:<name>`. Severity high. Fix: suffix the *name* part, preserving `cc@folder:`, and validate family through `chat::bridge_parts`.

3. The `push_channel` seam is told the wrong reach. `crates/bridge/src/rooms.rs:409` returns `"passing"` for every `fyi`; the room says an fyi that names you is `Addressed` (`crates/room/src/chat.rs:396`). Every push layer keying on `addressed` (the documented contract, `rooms.rs:398`) silences or downgrades mail the room addressed to this seat. Severity medium. Fix: call `letibot_room`'s match, and one test over both inputs.

4. `prompt_once` can deliver after reporting failure. `crates/bridge/src/fleet.rs:186-214` spawns an unjoined thread; the timeout arm returns "the daemon did not take the prompt" while `prompt_through` goes on to `prompt_from` (`:226-228`). A queue seat's retry then prompts the target twice. Severity medium. Fix: return the request id and settle on it, or make the timeout close the client.

5. Wire change under protocol 12. `Hello{share,family}` and `Request::MayPrompt` landed with `ROOM_PROTOCOL_VERSION=12` / `OLDEST_CLIENT=11` unchanged (`crates/room/src/wire.rs:15,19`). On a v11 coordinator the family is silently ignored, and the first `may_prompt` is an undecodable frame — `ReadFrame::Bad` (`crates/room/src/server.rs:5008-5011`) — so the bridge hears only "the room closed the connection" (`rooms.rs:960`), with no upgrade hint (`:1317`). Severity medium. Fix: gate `may_prompt` on `welcome.protocol`, or bump.

CONCESSIONS. Reply-matching by arrival order is bounded by the `call` mutex (`rooms.rs:655,925,1191`) — I could not build a crossing. Family mail does set `names_you` (`server.rs:3634`). `Attention::passes` agrees with `Chat::attends` (`chat.rs:509-521`). `Refused::NameInUse` exists (`room.rs:317`) and the suffix retry terminates; #2 is the truncation, not the recursion.

ANTICIPATION. Position 2 will cite R259 and `room_tools.rs`: that file is a fake coordinator (`:15`) and no test covers `wait-queue`, `suffixed`, or either `reach`. Position 3 will call the bridge a re-implementation of the room client; findings 2 and 3 are that duplication's price, and both fixes are "call the crate you already link".
