THESIS — The gate's primitives are text-shaped fact tables, and each one is sound only for the programs somebody hand-proved. A glob prefix over 145 seed patterns (`config/permission.json`), a six-program flag table (`permission.rs:506-528`), a 51-row destroy table over 190 documented programs (`intent.rs:863`, `documented_flags.rs`), and a command "shape" with operands holed (`code/src/shell.rs:2484`). Every safety property is a per-program proof that must be extended by hand, and R305 only patched the rows somebody found.

F1. **high** — The read-only narrowing covers 6 programs; the seed grants ~60. `evaluate_segment` (`permission.rs:423-441`) asks `write_or_exec_flag`, which knows only sed, sort, git, tree, xxd (`:509-528`). `rg*` is an allow (`permission.json:103`) and `rg` is `ReadFile` to the normaliser (`intent.rs:1080`). `rg --pre=./payload x` runs `/workspace/payload` per file: no flag is known, no intent is exec, and the allow arm (`adjudicate.rs:3363`) admits at every tier but always-ask, basis "nothing was consulted". `less -o` writes (`permission.json:144`). Failure: arbitrary code under a rule the operator wrote as a read. Change: derive the allowed flag set from the intent table per program, or allow only patterns with no wildcard.

F2. **high** — The shape holes the redirect target. `shape` prints redirects as `> <file>` (`shell.rs:2533-2541`), and an approved shape settles a later call (`adjudicate.rs:3493-3506`) — durably, warmed from the store (`open.rs:3086`). One "allow once" on `echo hi > /tmp/a` records `echo <args> > <file>`; later `echo x > crates/tools/src/adjudicate.rs` is admitted with no card. `card.rs:178` proves flags and operand counts, never the target. The author already made this exact exception for test runners (`boundary.rs:555-575`), one program at a time. Change: keep redirect targets and `--opt=value` values in the shape's key, or refuse shapes for calls carrying a redirect.

F3. **high** — `changes_its_own_rules` is a substring over one string. `touches_own_config` (`intent.rs:2227`) needs `letibot/permission.json`; `moves_only` exempts `cd` (`permission.rs:362`); a relative path is `HostOther`, not outside (`intent.rs:1654`, `adjudicate.rs:1524-1537`). `cd ~/.config/letibot && cp ./x permission.json` therefore fires no always-ask, is MayApprove, and at a Model-decider point (`adjudicate.rs:3558`) the oracle admits the write to the gate's own ruleset — `.config/letibot` is in no store list. Change: compare resolved targets, and treat the config directory as a store.

F4. **medium** — Two enums per concept, mapped by hand: `OptionKind` (5 variants, `adjudicate.rs:392`) vs `sessionlog::event::OptionKind` (`event.rs:673`), translated at `answers.rs:1112-1124`; `OnTimeout` Deny/Allow/AgentDecides (`adjudicate.rs:377`) vs Deny/Allow/Ask (`event.rs:687`) at `answers.rs:1067-1069`. And `is_allow`/`admits` (`:405`, `:416`) are byte-identical twins — tests use one, the gate the other, so a divergence compiles clean and is tested by neither.

F5. **medium** — The 6.8k-line normaliser is discarded by the cheaper rule: `sed` is `ExecuteCode` (`intent.rs:1094-1104`) while `sed -n` is a read (`permission.rs:656`), and permission is consulted first (`adjudicate.rs:3327`).

CONCESSIONS — The sed allow-list is careful (`s///e`, `w`, `-f` all refused); `never_hit` scans every non-content argument; `Tier::Blocked` precedes the permission allow. Position 1's list is largely closed where I looked; Position 2 is right that the gate works on the seed's real workloads — that is exactly the surface F1 breaks.
