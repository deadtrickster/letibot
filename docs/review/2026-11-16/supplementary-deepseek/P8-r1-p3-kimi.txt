THESIS. I6 is an invariant on a *copy* of authority. The tree has four authorities over "may this session do X" — the mode point (`mode.rs`), the gate's durable rungs (`adjudicate.rs`), `permission.json`, and the perimeter/seat the sandbox is built from — with four lifetimes and four narrowing rules. Only one of them (`mode.rs:564` `no_wider_than`) is written down, and it reads a scalar snapshot while the thing it bounds is edited behind its back. So both other positions argue about the ceiling while the room under it moves.

1. HIGH — narrowing does not narrow: `set_mode` clears a hand-written list. `AdjudicatedGate::set_mode` (`adjudicate.rs:3098-3110`) drops `grants`, `memory_session`, `unkept` and the ledger's `Scope::Session`. It does not touch `approved_shapes` (declared `:1388`, admitted `:3496-3509` as "you approved this shape before, in this project", seeded per project at `:1867`), nor `permission.json`, which is evaluated *before* the mode (`adjudicate.rs:3325`) and admits at `:3363` with "nothing was consulted", nor queue-scope grants (kept on purpose, `:1618-1622`). Scenario: the operator at `allow-all` approves `bash cargo test` once; `/mode always-ask`; the next `cargo test` runs with no card, while `mode.rs:296-299` promises "every one of them asks you, every time". Change: one ceiling value; every rung stamps the point it was minted under; the drop is derived from the ceiling, not enumerated.

2. HIGH — the project row is written by doors that never learned whether the point was carried, and then outranks `--mode` and fails the open. `sessions.rs:4910` writes `store.set(&workspace, mode)` *before* the move at `:4938-4945`, and `:4971` admits the row now applies to "every LATER session" regardless. `turns.rs:3305-3312` calls `modes::record` whatever `moved` was (`modes.rs:291` `st.set`). At open, `open.rs:707` lets that row replace `cfg.mode` and `:2895-2899` turns an uncarryable row into `HarnessError::Setup`; `parts.rs:14` says the row, not the flag, is the point. Scenario: a VM session (has `Confinement`) does `/mode allow-all` → row `allow-all`, no consent; a local session for that project now cannot open at all, and `--mode always-ask` does not help because the row wins. Change: write the row only from a root session whose move succeeded; an uncarryable stored row must refuse the row (with a note), never the session.

3. MEDIUM — the seat is rendered from the opening point, so `/mode` never reaches the sandbox. Egress is baked at open (`open.rs:1302`; `:838-847` → `seat.rs:160-176`), and `set_mode_consented` (`harness.rs:766-790`) touches cfg, the cell and the gate only. Open `read-only` (`Egress::Denied`), `/mode writes-allowed`: the mode seats the network as `Ask` and the summary promises the network asks, but every confined command gets an empty netns, so the card's yes is followed by a failure. Reverse: open wide, narrow, and any exec admitted by finding 1 reaches the network at a point that says nothing leaves the box. Change: render the seat from the effective point per command, or re-seat inside the move.

4. MEDIUM — three doors, three persistence outcomes. The worker door writes project+session rows; the turn door writes them under a different condition; `answer_mode_confirm` (`harness.rs:1005-1085`) calls only `set_mode_consented` and writes nothing, while `mode.rs:400-404` promises the confirmation "is RECORDED with the project and the session … so it survives a restart". The bridge's confirmed allow-all is lost at restart. Change: one door owns persistence.

CONCESSIONS. A child cannot send `/mode` at all (`children.rs:700-701`), so no child rewrites the project row. All three widening doors do check (`sessions.rs:4888`, `turns.rs:3294`, `harness.rs:765`) and the R306 tests fail without it. Refusing by name instead of silently downgrading is right.

To position 1: the restart gap is this same disease — `harness.rs:805-824` compares against a copied cell, and `open.rs:2214-2220` seeds it from the child's own point, so the ceiling has no walk back to the parent. To position 2: the tests prove refusal-by-name and nothing else; none crosses a narrowing with an approved shape or a permission rule.
